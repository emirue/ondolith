# D83. 브라우저 수동 테스트 시나리오

빈 데이터베이스에서 시작해 **설치 → 운영 → 커머스 한 바퀴**를 브라우저로 직접
도는 절차. 자동 테스트가 못 보는 것을 본다 — 화면이 실제로 그려지는지, 링크가
살아 있는지, 디자인이 적용되는지, 흐름이 사람 손에서 끊기지 않는지.

`make test-integration` 이 900건을 돌지만 그것은 **핸들러가 옳은 응답을 만드는가**
까지다. 응답이 브라우저에서 쓸 만한 화면이 되는지는 여기서만 확인된다.

## 준비

```bash
go build -o /tmp/ondolith-demo ./cmd/ondolith
sh scripts/testdb.sh up                       # PostgreSQL 컨테이너
docker exec <pg> psql -U ondolith -d postgres \
  -c "DROP DATABASE IF EXISTS demo;" -c "CREATE DATABASE demo OWNER ondolith;"
mkdir -p /tmp/ondolith-run && cd /tmp/ondolith-run
/tmp/ondolith-demo -addr 127.0.0.1:8099 -config ./ondolith.json
```

설정 파일이 없으므로 설치 마법사가 뜬다. **이 파일이 없는 상태에서 시작하는 것이
1단계의 전제다** — 있으면 P-001 이 아니라 운영 트리가 뜬다.

## 판정 방식

각 단계는 **무엇을 보면 통과인지**를 적는다. "잘 뜬다"는 판정이 아니다.

- 화면이 200 이고 기대한 문구가 보이면 ✅
- 500·404·빈 화면·깨진 링크·적용되지 않은 스타일은 ❌ 이고, **고친 뒤 그 단계부터
  다시 돈다**
- 자동 테스트로 재현 가능한 실패는 테스트를 먼저 쓴다 ([KARPATHY](../.ai/KARPATHY.md) 4절)

## 1단계 — 설치 (P-001, P-002)

| # | 하는 일 | 통과 기준 |
|---|---|---|
| 1.1 | `/` 로 접속 | `/install` 로 리다이렉트 (P-002) |
| 1.2 | DB 접속 정보 입력 (`demo`) | 다음 단계로 넘어간다 |
| 1.3 | 사이트 이름·관리자 계정 입력 | 설치 완료 화면 |
| 1.4 | 설치 완료 직후 `/` | **재시작 없이** 홈이 뜬다 (트리 교체) |
| 1.5 | `/install` 재접속 | 설치된 뒤에는 접근 불가 |
| 1.6 | `ondolith.json` 확인 | 파일이 생겼고 `database_url` 이 들어 있다 |

## 2단계 — 인증 (P-101~P-113)

| # | 하는 일 | 통과 기준 |
|---|---|---|
| 2.1 | `/login` 에 관리자 계정 | `/admin` 접근 가능 |
| 2.2 | 틀린 비밀번호 5회 | 429 와 재시도 안내 (FR-209) |
| 2.3 | `/signup` 으로 일반 회원 가입 | 가입 후 **로그인 상태로** 홈 (M16 이 고친 자리) |
| 2.4 | `/me` | 표시 이름·이메일이 보인다 |
| 2.5 | `/me/password` 로 비밀번호 변경 | 변경 후에도 **로그인이 유지된다** |
| 2.6 | `/logout` → `/me` | 로그인 화면으로 밀린다 |

## 3단계 — 디자인·테마 (A-201, A-202, P-201, P-906)

| # | 하는 일 | 통과 기준 |
|---|---|---|
| 3.1 | 홈의 개발자 도구 Network | `/static/...` CSS 가 **200** 이다 (404 면 디자인이 안 붙은 것) |
| 3.2 | 홈 렌더 | 사이트 이름이 헤더에 보이고 스타일이 적용돼 있다 |
| 3.3 | `/admin/settings` 에서 사이트 이름 변경 | 홈 헤더가 바뀐다 |
| 3.4 | `/admin/themes` | 내장 테마가 목록에 있고 활성 표시가 있다 |
| 3.5 | 좁은 폭(모바일)으로 홈 | 가로 스크롤이 생기지 않는다 |

## 4단계 — 콘텐츠 (A-301~A-309, P-202~P-212)

| # | 하는 일 | 통과 기준 |
|---|---|---|
| 4.1 | `/admin/pages` 에서 페이지 생성·발행 | `/{slug}` 로 보인다 |
| 4.2 | `/admin/boards` 에서 게시판 생성 | `/board/{slug}` 가 열린다 |
| 4.3 | 글쓰기 (P-205) | 목록과 상세에 나타난다 |
| 4.4 | 첨부파일 업로드 후 다운로드 (P-211) | 올린 파일이 그대로 내려온다 |
| 4.5 | 댓글 작성·수정·삭제 | 각 동작 뒤 화면이 갱신된다 |
| 4.6 | `/search` 로 방금 쓴 글 검색 | 결과에 나온다 |
| 4.7 | `/sitemap.xml`, `/robots.txt` | 200 이고 방금 만든 페이지가 sitemap 에 있다 |

## 5단계 — 커머스 준비 (A-509, A-501~A-503, A-512, A-209)

| # | 하는 일 | 통과 기준 |
|---|---|---|
| 5.1 | `/admin/settings` 에서 사이트 유형을 커머스로 | 관리 메뉴에 상품·주문이 생긴다 |
| 5.2 | `/admin/categories` 카테고리 생성 | 목록에 보인다 |
| 5.3 | `/admin/products` 상품 생성 | `/shop` 에 보인다 |
| 5.4 | `/admin/products/{id}/variants` 옵션·재고 입력 | 상세에서 옵션 선택이 된다 |
| 5.5 | `/admin/commerce/policy` 배송비·반품비 정책 | 저장되고 다시 열면 남아 있다 |
| 5.6 | `/admin/settings/payment` 에서 PG 를 「사용 안 함」 | `/checkout` 이 **503** 으로 거절한다 |

## 6단계 — 구매 흐름 (P-301~P-410)

| # | 하는 일 | 통과 기준 |
|---|---|---|
| 6.1 | `/shop` 목록 → 상세 | 가격·재고가 보인다 |
| 6.2 | 품절 조합 선택 | 담기가 막힌다 |
| 6.3 | 장바구니 담기·수량 변경·삭제 | 합계가 따라 바뀐다 |
| 6.4 | `/checkout` 주문서 | 배송비가 정책대로 붙는다 |
| 6.5 | 결제 설정을 토스로 바꾼 뒤 `/checkout/pay` | 결제창 호출까지 간다 (승인은 D73) |

**승인 왕복(P-408)은 여기서 끝나지 않는다** — 브라우저가 발급한 `paymentKey` 가
필요하고, 그것은 [D73](73-toss-verification.md) 의 절차다.

## 기록

발견한 것은 여기에 남기지 않는다 — **고치고, 재현 테스트를 남기고, 커밋 메시지에
적는다.** 이 문서는 절차이지 결과 보관소가 아니다. 반복된 실수는
[MISTAKES](../.ai/MISTAKES.md) 로 간다.
