# D83. 브라우저 수동 테스트 시나리오

빈 데이터베이스에서 시작해 **설치 → 운영 → 커머스 한 바퀴**를 브라우저로 직접
도는 절차. 자동 테스트가 못 보는 것을 본다 — 화면이 실제로 그려지는지, 링크가
살아 있는지, 디자인이 적용되는지, 흐름이 사람 손에서 끊기지 않는지.

`make test-integration` 이 900건을 돌지만 그것은 **핸들러가 옳은 응답을 만드는가**
까지다. 응답이 브라우저에서 쓸 만한 화면이 되는지는 여기서만 확인된다.

## 준비

```bash
go build -o /tmp/ondolith-demo ./cmd/ondolith
sh scripts/testdb.sh up                       # PostgreSQL 컨테이너
docker exec <pg> psql -U ondolith -d postgres \
  -c "DROP DATABASE IF EXISTS demo;" -c "CREATE DATABASE demo OWNER ondolith;"
mkdir -p /tmp/ondolith-run && cd /tmp/ondolith-run
/tmp/ondolith-demo -addr 127.0.0.1:8099 -config ./ondolith.json
```

설정 파일이 없으므로 설치 마법사가 뜬다. **이 파일이 없는 상태에서 시작하는 것이
1단계의 전제다** — 있으면 P-001 이 아니라 운영 트리가 뜬다.

## 케이스 ID

각 행은 `T<단계>.<번호>` 다. 커밋 메시지와 이 문서 밖에서 **그 케이스를 가리켜
말할 수 있게** 하기 위한 것이다 — "환불 화면이 이상하다" 와 "T7.4 가 실패한다"
는 다시 확인하는 비용이 다르다.

## 자동으로 도는 부분 (다섯)

| 명령 | 무엇을 보는가 | 무엇을 잡는가 |
|---|---|---|
| `make e2e` | 흐름 | 설치부터 부분 환불까지 한 바퀴 |
| `make screens` | 응답 | 모든 GET 화면이 열리는가 (D11 의 표) |
| `make crawl` | 링크 | 화면이 만든 주소가 실제로 열리는가 · 홈에서 눌러서 닿는가 |
| `make ui` | **좌표** | 브라우저에 그려 놓고 잰다 — 넘침·정렬·터치 크기. 라이트·다크 두 벌 |
| `make shots` | **픽셀** | 같은 브라우저로 552장을 찍어 `shots/` 에 남긴다 — 사람이 본다 |

다섯은 겹치지 않는다. 앞의 셋은 **HTTP 응답까지만** 본다 — 200 을 받으면 통과하므로
글자가 상자 밖으로 나가든 표가 화면을 넘든 초록이다. `make ui` 는 Chromium 을
띄워 375·768·1280px 에 그린 뒤 `getBoundingClientRect` 로 잰다.

**좌표가 재지 못하는 것이 남는다.** 빈 상자는 넘치지도 잘리지도 않고, 작성자
줄에 이메일이 찍혀 있어도 폭은 정상이며, 밑줄 링크와 초록 버튼은 같은 높이다.
`make shots` 는 `make ui` 와 **같은 시드·같은 세션·같은 브라우저**로 PNG 를 남긴다
— 마지막 한 걸음만 갈라진다. 두 벌로 두면 「찍은 화면」과 「잰 화면」이 서로 다른
상태가 되고, 눈으로 본 것이 증거가 되지 않는다.

`make shots` 로 실제로 찾은 것: 게시물 작성자 줄의 **관리자 이메일 노출**(NFR-212),
값 없는 커스텀 필드의 **빈 회색 막대**, 브라우저 기본 모양으로 남은 **약관 상자**,
버튼이 아니라 밑줄 링크였던 **「주문하기」**, 그리고 라우트도 핸들러도 있는데
누를 자리가 없던 **장바구니 「빼기」**(P-404). 좌표 검사는 다섯 중 하나도 잡지
못했다 — 전부 «정상 크기의 잘못된 것» 이기 때문이다.

머리·본문·바닥의 세로축 어긋남은 찍어 보고 알았지만 **좌표로 잴 수 있어서**
`make ui` 의 규칙이 됐다. 눈이 찾은 것 중 기계가 지킬 수 있는 것은 기계에 넘긴다.

**색 대비도 이제 잰다.** 좌표가 아니라 색이라 눈으로만 보던 자리였는데,
`getComputedStyle` 의 전경·배경으로 WCAG 2.1 AA 를 계산해 규칙이 됐다 — 552 조합을
처음 돌리자 **두 곳이 걸렸고 둘 다 CSS 특이성 버그**였다: 페이지네이션의 현재
페이지 칩이 강조색 배경 위에 본문 색으로 그려지고 있었다(라이트 2.84:1 · 다크
1.87:1). 의도한 색이 한 번도 적용된 적이 없었다.

**여기서도 못 보는 것이 남는다.** 552장을 사람이 다 보지는 않았다 — 목록과 닫는
방법은 [D85](85-gaps.md)의 `GAP-01`이다.

**CSS 가 두 벌이면 검사도 두 벌이다.** 라이트만 재던 동안 다크는 아무도 본 적이
없었고, 처음 찍어 보니 **관리자 콘솔의 다크가 죽어 있었다** — 서버가 기본값을
`data-admin-theme` 로 찍어 채워서 `:root:not([data-admin-theme])` 가 영원히
매치되지 않았다. 스무 줄짜리 다크 콘솔이 죽은 코드였고, 그것을 고를 화면도
없어서 관리자 화면을 어둡게 만들 방법이 아예 없었다.

**목록을 손으로 적지 않는다.** `make screens` 와 `make ui` 는 둘 다 D11 과
대조한다 — 새 화면이 생기면 검사에서 조용히 빠지는 것을 막는다. 재지 않는 것이
정상인 화면은 스크립트에 이유와 함께 적혀 있다.

각각이 처음 돌았을 때 나온 것:

- `make screens`: **화면을 여는 것만으로 500 이 나던 곳 둘**, **D11 이 구현과
  다른 라우트 19개**. 흐름 테스트는 그 화면들을 지나가지 않았다.
- `make ui`: **188 건.** 관리자 표 아홉이 스크롤 상자 밖에 있었고, 글쓰기 폼이
  상자 밖으로 28px 밀렸으며, 버튼 높이가 네 종류였다. 그리고 **일곱 화면의 표가
  빈 상태로만 그려지고 있었다** — 행이 없으면 열이 좁아져 넘치지 않으므로 그
  화면의 반응형 동작은 검사되지 않은 채 통과한다.
- `make crawl`: **홈에서 눌러서 닿는 화면이 9~11개뿐**이었다. `/admin/`·
  `/cart`·`/orders`·`/search` 로 가는 링크가 사이트 어디에도 없었고, 장바구니는
  상품을 `/shop/p/{UUID}` 로 가리키는데 라우트는 `{slug}` 였다. 앞의 두 검사는
  전부 초록이었다.


`make e2e` 가 **T1.1 ~ T7.7 중 HTTP 로 확인 가능한 것을 전부 재실행한다**
(`scripts/e2e.sh`). 빈 데이터베이스에서 설치를 마치고 게시판·상품·주문·부분
환불까지 한 바퀴를 돌며 각 단계의 응답과 데이터베이스 상태를 단언한다.

**남는 것은 눈으로 봐야 하는 것뿐이다** — 스타일이 붙었는지, 표가 읽히는지,
좁은 화면에서 무너지지 않는지. 그 항목은 아래 표에 👁 로 표시했다. 나머지는
스크립트가 이미 확인했으므로 사람이 다시 돌 필요가 없다.

## 판정 방식

각 단계는 **무엇을 보면 통과인지**를 적는다. "잘 뜬다"는 판정이 아니다.

- 화면이 200 이고 기대한 문구가 보이면 ✅
- 500·404·빈 화면·깨진 링크·적용되지 않은 스타일은 ❌ 이고, **고친 뒤 그 단계부터
  다시 돈다**
- 자동 테스트로 재현 가능한 실패는 테스트를 먼저 쓴다 ([KARPATHY](../.ai/KARPATHY.md) 4절)

## 자동/수동 경계

| | 개수 | 무엇 |
|---|---|---|
| `make e2e` 가 돈다 | **65** | 응답 코드·리다이렉트·데이터베이스 상태 |
| 👁 사람이 본다 | 14 | 스타일이 붙었는지 · 표가 읽히는지 · 좁은 화면 |

**둘을 섞지 않는다.** 스크립트가 확인한 것을 사람이 다시 도는 것은 시간 낭비이고,
사람만 볼 수 있는 것을 스크립트가 도는 척하면 그 항목은 아무도 안 본다.

`make e2e` 는 `make check` 에 넣지 않는다 — 도커와 빌드된 바이너리가 필요해
1분 가까이 걸린다. 커머스나 설치 흐름을 건드렸으면 손으로 돌린다.

## 기록

발견한 것은 여기에 남기지 않는다 — **고치고, 재현 테스트를 남기고, 커밋 메시지에
적는다.** 이 문서는 절차이지 결과 보관소가 아니다. 반복된 실수는
[MISTAKES](../.ai/MISTAKES.md) 로 간다.
