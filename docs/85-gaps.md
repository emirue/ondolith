# D85. 결함·미검증 대장

> **초록 게이트가 「확인했다」를 뜻하지 않는 항목을 여기 한 곳에만 적는다.**
> 아직 *정하지* 않은 것은 [D18](18-open-decisions.md)이다 — 이 문서는 정해졌는데
> 아직 *하지 않았거나*, 했는데 *확인되지 않은* 것을 담는다.

[D18](18-open-decisions.md)이 미결을 한 곳으로 모은 이유가 그대로 여기에도 적용된다:
문서마다 흩어 두면 고쳐도 안 지워 **닫힌 항목이 열린 채로 남고**, 같은 항목이 여러 곳에
중복된다. 게이트가 전부 초록인데 무엇이 확인되지 않았는지 아무도 말할 수 없는 상태가
이 저장소에서 반복됐다 ([M3](../.ai/MISTAKES.md), [M4](../.ai/MISTAKES.md)).

## 규칙

| # | 규칙 |
|---|---|
| 1 | 대장은 **이 문서에만** 둔다. ID는 `GAP-##`(검증 공백)과 `BUG-##`(알려진 결함) |
| 2 | 닫으면 **행을 지운다.** `해결됨`으로 남기지 않는다 — 대장이 커지면 아무도 안 읽는다 |
| 3 | 이 항목을 언급할 때는 **반드시 `GAP-##`/`BUG-##`를 인용**한다. 대장에 없는 ID를 가리키면 `make check` 실패 — **문서(`*.md`)·코드(`*.go`)·마이그레이션(`*.sql`) 전부**를 훑는다. `BUG-##`가 설명하는 자리는 나중에 고칠 코드이고, 그 옆의 `// BUG-01` 주석이 가장 오래 남는 인용이다 |
| 4 | 게이트를 늘려 자동으로 잡히게 되면 그 행은 닫힌다. **대장은 자동화의 대기열이다** |
| 5 | 「의도적으로 확인하지 않기로 한 것」은 대장이 아니라 그 검사 스크립트에 이유와 함께 적는다 |

## GAP — 검증 공백

**게이트가 초록이어도 확인되지 않은 것.** 각 행은 「무엇을 모르는가」와 「무엇을 하면
닫히는가」를 함께 적는다. 닫는 방법이 없는 행은 대장이 아니라 비목표다.

| ID | 확인되지 않은 것 | 왜 게이트가 못 잡나 | 닫는 방법 |
|---|---|---|---|
| GAP-01 | **스크린샷 552장 중 사람이 본 것은 12장뿐이다** | `make ui`는 좌표만 잰다 — 색 대비·어색한 문구·잘못된 값은 정상 크기로 그려진다 | 나머지를 훑고, 눈이 찾은 것 중 좌표로 잴 수 있는 것은 `make ui` 규칙으로 옮긴다 ([D83](83-browser-test.md)) |
| GAP-03 | **실제 PG(토스)로 결제 한 바퀴를 돈 적이 없다** | `make e2e`는 어댑터를 가짜로 두고 돈다. 승인·취소·웹훅의 실제 응답 모양은 확인되지 않았다 | `ONDOLITH_TOSS_TEST_SECRET`으로 `make test-toss` ([D73](73-toss-verification.md)) |
| GAP-04 | **`golang.org/x/crypto@v0.54.0`에 수정 없는 취약점이 하나 있다** (GO-2026-5932, `openpgp` 미유지보수) | 우리 코드가 그 패키지를 **호출하지 않아** `govulncheck`가 통과시킨다. 의존성 그래프에는 남아 있다 | 상위 의존성이 `openpgp`를 떼거나 x/crypto가 갈라질 때까지 대기. `make vuln`을 릴리즈마다 돌려 상태를 다시 읽는다 (NFR-209) |
| GAP-06 | **`make ui`·`make shots`는 어디서도 자동으로 돌지 않는다** | 브라우저가 필요해 오프라인 게이트에 넣을 수 없다. 누가 안 돌리면 UI 결함은 그대로 지나간다 | `.github/workflows/ci.yml`에 브라우저 잡을 추가한다. **DB 쪽은 닫혔다** — 같은 파일의 `integration` 잡이 PostgreSQL을 붙여 `make test-integration`을 돌리므로, DSN이 없어 건너뛰던 444건(46%)은 이제 CI에서 실행된다. 남은 것은 `ui.sh`가 쓰는 `docker exec` 경로를 서비스 컨테이너에 맞추는 일이다 |
| GAP-07 | **[D19](19-screen-io.md) 오류표의 상태코드 300여 건이 구현과 대조된 적이 없다** | checkdocs 30-1 은 「0.3 규약 안의 코드인가」만 본다. 어느 행이 어느 핸들러의 어느 분기인지는 상황 칸(자연어)에 있어 기계가 못 읽는다 — 재고 네 행이 `400`으로 적힌 채 구현이 `422`였던 것을 사람이 읽고서야 찾았다 | 상황 칸에 오류 식별자(`ErrOutOfStock` 등)를 적어 코드와 이을 수 있게 하거나, 화면별 통합 테스트가 표의 코드를 단언하게 한다. 후자는 GAP-06의 CI 잡이 먼저 있어야 값이 있다 |

### 의도적으로 재지 않는 화면

**대장이 아니다.** [D11](11-screens.md)의 GET 화면 중 `make ui`가 재지 않는 17개는
`scripts/ui.sh`의 `ui_skip_reason()`에 **이유와 함께** 적혀 있고, 목록에 없는 화면이
빠지면 그 자리에서 실패한다. 토큰이 있어야 열리는 화면(P-105·P-112), 결제창이 되돌려
보내는 화면(P-407~P-410), 그릴 것이 없는 응답(P-901·P-902·P-906·P-907) 등이다.

## BUG — 알려진 결함

**재현되고 원인이 밝혀졌는데 아직 고치지 않은 것.** 원인을 모르면 여기가 아니라
조사 대상이다.

| ID | 결함 | 영향 | 원인 | 관련 |
|---|---|---|---|---|
| BUG-01 | **관리자 대시보드가 비어 있다** — 「왼쪽 메뉴에서 고르세요」 한 줄뿐 | 첫 화면이 아무것도 알려주지 않는다. 넓은 화면에서 사이드바 옆이 통째로 빈다 | 요약 위젯이 구현된 적이 없다. FR-702는 Phase 1의 **선택** 항목이라 미구현이 정상이다 | FR-702 / A-101 / [D80](80-roadmap.md) |
| BUG-02 | **관리자 배색(`admin.theme`)을 고르는 화면이 없다** | 1a·1d·1e를 고를 방법이 없다. 라이트/다크는 OS 설정을 따르므로 막히지 않는다 | 설정 키는 부팅 때 읽지만(`app.go`) 그것을 저장하는 폼이 없다. `/admin/themes`(A-202)는 **사이트** 테마용이다 | A-202 / [D13](13-screens-admin.md) |

## 닫는 순서

**GAP-06 → GAP-01** 순이 값이 크다.

1. **GAP-06**을 먼저 닫는다. 검사가 자동으로 돌지 않으면 나머지를 아무리 늘려도
   돌리는 사람에게 달린 채로 남는다.
2. **GAP-01**은 사람이 하는 일이라 한 번에 끝나지 않는다 — 훑는 동안 나오는 것을
   규칙으로 옮기면 다음 훑기가 가벼워진다. 색 대비는 이미 규칙이 됐다: 눈이
   「좀 흐린데」라고 말했을 자리 두 곳을 `make ui` 가 수치로 잡아 냈고, 둘 다
   CSS 특이성 버그였다.

`BUG-01`·`BUG-02`는 기능 추가이고 게이트를 막지 않는다. Phase 우선순위는
[D80](80-roadmap.md)이 정한다.
