## 검토 결과

**핵심 코드 변경(권한 검증)은 견고하다.** `install.go`의 CTE는 실제로 `user_roles`에 admin 역할을 부여하고, `internal/install/integration_test.go`에 역할·`is_superuser` 단언이 추가돼 있음을 직접 확인했다(diff에는 안 보이지만 파일에 존재). `userfields_integration_test.go`도 `is_admin` 대신 `user_roles` 카운트로 바꿔 실제로 더 엄격해졌다. `migrations/integration_test.go`도 백필(00003)이 컬럼 삭제(00006)보다 먼저 도는 순서를 정확히 검증한다. assertion 약화나 테스트 우회는 찾지 못했다.

**발견한 문제: `docs/30-data-model.md`의 "현재 스키마" 표가 갱신되지 않았다.**

- 파일: `docs/30-data-model.md:240`
- 이 diff는 CHANGELOG, D15, D19, D20, D80, D81 등 `is_admin` 관련 문서 6곳을 갱신했지만, 정작 스키마의 정본으로 취급되는 `docs/30-data-model.md`의 `users` "현재 스키마" 표는 손대지 않았다. 그 표는 여전히 `| is_admin | boolean NOT NULL DEFAULT false | **임시.** Phase 1에서 RBAC로 교체 |` 를 싣고 있다 — 컬럼은 00006이 이미 지웠는데 "임시로 남아있다가 교체될 것"이라는 서술이 지금은 사실과 다르다.
- 같은 문서 219~228행 부근의 서문은 "그 절의 컬럼 정의는 이제 계획이 아니라 마이그레이션과 대조되는 명세다 — 어긋나면 `make check`가 실패한다"고 명시한다. 즉 이 표는 스스로 "마이그레이션과 항상 일치함을 기계적으로 보장한다"고 주장하는 자리다.
- `scripts/checkdocs.sh`의 15-2절(라인 ~691 이하) 코드를 직접 읽었다: Perl 파서가 각 마이그레이션의 `-- +goose Up` ~ `-- +goose Down` 구간에서 `CREATE TABLE`과 `ALTER TABLE ... ADD COLUMN`만 수집하고, **`DROP COLUMN`은 전혀 처리하지 않는다.** 그 결과 `users.is_admin`은 00001의 `CREATE TABLE`에서 한 번 수집된 뒤 영구히 "존재해야 하는 컬럼" 목록에 남는다 — 00006이 지워도 체커의 기대 목록에서는 빠지지 않는다.
- `internal/migrations/*.sql`을 전수 확인한 결과 **00006이 이 프로젝트 최초로 Up 절에 `DROP COLUMN`을 쓴 마이그레이션**이다(CHANGELOG의 "첫 파괴적 마이그레이션" 서술과 일치). 즉 이 diff가 처음으로 체커의 DROP COLUMN 처리 공백을 실제로 건드렸는데, 그 공백을 인지하거나 고치지 않고 넘어갔다.
- 실제 영향: 지금 상태(문서에 `is_admin` 잔존)는 체커의 맹점과 우연히 맞아떨어져 `make check`를 통과할 가능성이 높다 — 반대로 누군가 문서를 정확하게 고쳐 그 행을 지우면 체커가 "마이그레이션에 있는 컬럼이 D30에서 빠짐"으로 **오탐 실패**를 낼 것이다(같은 파일 386~390행의 selftest 주입 케이스가 정확히 이 경로를 흉내낸다). 즉 이 PR의 요지("RBAC 이관 후 `is_admin`을 완전히 지운다")를 문서 차원에서는 아직 완결하지 못했고, 그걸 바로잡을 경로도 지금 체커로는 막혀 있다.
- `selftest.sh`의 D30 관련 주입 케이스(135행, 386~400행)에는 "컬럼이 삭제된 뒤에도 문서가 갱신되지 않는" 시나리오에 대한 주입이 없다 — 이번 세션이 최초로 이 경로를 실사용했는데도 회귀 테스트가 추가되지 않았다.

이 문제는 기능/보안 로직 자체를 깨뜨리지는 않지만(권한 검증 코드·테스트는 실제로 개선됐다), 세션이 "루프 종료 조건 전부 달성"이라 자평하며 문서 전수 갱신을 자랑한 것과 달리, 스스로 "기계적으로 대조된다"고 주장하는 정본 문서 한 곳을 놓쳤고, 그 사각지대가 검증 도구 자체의 결함(DROP COLUMN 미처리)에서 비롯된 것임을 확인했다.
