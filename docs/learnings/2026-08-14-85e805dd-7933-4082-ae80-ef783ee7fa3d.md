## 반려 사유 (콜드 리뷰어)

## 검토 결과

**1. `scripts/selftest.sh` — 새로 추가된 사전조건 단언이 다운스트림 검사를 게이팅하지 않는다 (중간 심각도)**

새로 추가된 블록(688번대):

```sh
if PATH=$NO_DOCKER command -v docker >/dev/null 2>&1; then
	err "docker 없는 PATH 를 만들지 못했다 — 아래 두 검사가 무의미하다"
elif ! PATH=$NO_DOCKER command -v sh >/dev/null 2>&1; then
	err "docker 없는 PATH 에 sh 조차 없다 — 스크립트가 docker 검사에 닿지 못한다"
else
	ok "docker 만 없는 PATH 를 만들었다 (sh 는 있다)"
fi

run_vr "$NO_DOCKER"
```

`err`는 `fail=1`만 세팅하고 스크립트를 중단시키지 않는다(파일 하단 `if [ "$fail" -ne 0 ]; then exit 1; fi`). 따라서 사전조건이 실패해도(예: `NO_DOCKER`에 여전히 `docker`가 보이는 경우) 바로 아래 `run_vr "$NO_DOCKER"`와, 조금 뒤 `integration.sh` 실행 블록은 그대로 깨진 `$NO_DOCKER`를 대상으로 계속 돌고, 각자 독립적으로 `grep -q "docker"` 결과에 따라 자기만의 `ok`/`err`를 찍는다. 이건 이 파일이 다른 곳(`run_vr -` 블록의 "M10 — 다른 이유로 거부했다" 분기, `detected()` 헬퍼)에서 명시적으로 경계하는 바로 그 M10 패턴이다 — "의도한 검사가 다른 이유로 통과/실패해 정작 증명되지 않는" 상황. `fail=1`이 이미 세팅되어 전체 selftest는 결국 빨간불이 되므로 게이트 자체는 안전하지만, CHANGELOG가 주장하는 "그 단언이 없으면 앞선 두 판처럼 검사가 엉뚱한 이유로 통과·실패한다"는 문구는 다운스트림 개별 `ok`/`err` 라벨에 대해서는 정확히 해결되지 않았다 — 사전조건 `err` 옆에 무관한 `ok`가 함께 찍힐 수 있다.

**2. `scripts/selftest.sh` — PATH 심링크 루프가 디렉터리를 걸러내지 않는다 (낮은 심각도, 잠재적)**

```sh
for nd_f in "$nd_dir"/*; do
	nd_b=${nd_f##*/}
	[ "$nd_b" = docker ] && continue
	[ -x "$nd_f" ] || continue
	...
	ln -s "$nd_f" "$NO_DOCKER/$nd_b" 2>/dev/null
done
```

`[ -x ]`는 탐색 가능한(대부분의) 디렉터리에도 참이다. PATH 항목 안에 서브디렉터리가 있으면(예: `node_modules/.bin` 스타일 레이아웃) 그 이름 그대로 `NO_DOCKER`에 "명령"처럼 심링크된다. 현재 CI의 PATH 구성에서는 문제를 안 일으키겠지만, "지금은 동작하지만 나중에 깨질 추상화"에 해당한다 — 파일 타입 검사(`[ -f ]`)가 빠져 있다.

두 항목 모두 전체 게이트를 무력화하는 수준은 아니며(1은 `fail=1`로 여전히 잡히고, 2는 발현 조건이 좁다), assertion 삭제·약화나 테스트 입력 하드코딩, 미완성 구현 같은 심각한 패턴은 발견하지 못했다. `NFR-209` 인용은 `docs/81-work-breakdown.md`(W4-02, GAP-04)에서 이미 "릴리즈 전 취약점 게이트" 의미로 확장 사용된 선례가 있어 문제로 보지 않았다.
