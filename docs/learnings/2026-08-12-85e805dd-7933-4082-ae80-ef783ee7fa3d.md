- `internal/app/handler_shop.go:264-273` — `cartUpdate`에 `quantity` 0 이하/비정수 시 400을 반환하는 검증을 추가했다. CHANGELOG는 이것을 "장바구니 수량에 오타를 내면 항목이 지워졌다" 버그의 수정으로 명시하고, `docs/19-screen-io.md:942,959`(D19 P-403, FR-602/FR-603)는 정확히 이 동작("quantity 0 이하/비정수 → 400")을 요구사항으로 못 박아 두었다.
- 그런데 이 diff에는 이 경로를 실행하는 테스트가 **하나도 없다**. 직접 확인한 근거:
  - `grep -rn "MethodPatch" internal/` → 저장소 전체에서 0건. PATCH `/cart/items/{id}`를 호출하는 테스트가 어디에도 없다.

  - `grep -rn "수량은 1 이상" internal/` → 새 에러 문구가 소스 파일(`handler_shop.go:269`) 한 곳에만 있고 어떤 테스트도 이 문자열을 기대하지 않는다.
- 이번 diff는 `internal/commerce/reconcile_test.go`, `internal/auth/token_test.go`, `internal/httpsec/headers_test.go`처럼 다른 수정마다 꼼꼼히 테스트를 붙였는데, 같은 세션이 고쳤다고 주장하는 데이터 유실 버그(P-403)에는 예외적으로 검증이 빠졌다. `strconv.Atoi` 파싱 + 분기라는 점에서 CLAUDE.md가 명시한 "비자명한 로직(분기·파서·금액 경로)에는 테스트를 하나 남긴다" 규칙에 해당하는 자리이기도 하다.
