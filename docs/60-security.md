# D60. 보안

> 이 프로젝트에서 가장 위험한 영역이다. 그누보드가 20년간 반복해서 뚫린 지점이며,
> 새로 쓴 코드에는 그 20년치 경험이 없다. 요구사항: [D10](10-requirements.md) NFR-2xx.

## 첫 번째 규칙

**인증·세션·CSRF·업로드 검증을 자작하지 않는다** (NFR-201).

"우리 상황엔 간단한 걸로 충분하다"는 판단이 사고의 시작이다. 검증된 라이브러리를 쓴다.
지정 목록은 [.ai/DECISIONS.md](../.ai/DECISIONS.md) DEC-1.

## 위협 모델

배포형 제품이라 우리가 운영하지 않는 서버에서 돈다. 운영자는 보안 전문가가 아니다.

| 위협 | 대상 | 대응 |
|---|---|---|
| 미설치 서버 점유 | 설치 직후 창 | 설치를 빨리 끝내도록 안내. 부팅 시 경고 로그. CSRF는 설치 폼에도 적용 |
| 설정 파일 유출 | DB 비밀번호 | 파일 권한 0600. 웹루트 밖 |
| SQL 인젝션 | 게시판 검색·필터 | 파라미터 바인딩 강제 (NFR-202) |
| 저장형 XSS | 글·댓글 본문 | 기본 이스케이프. `template.HTML` 사용 시 사유 주석 (NFR-203) |
| 악성 파일 업로드 | 첨부·테마 | 4중 검증 (아래) |
| 세션 탈취·고정 | 로그인 | HttpOnly·SameSite·Secure, 로그인 시 ID 재발급 (FR-204) |
| 관리자 무차별 대입 | 로그인 | rate limiting (NFR-207) |
| 결제 금액 위변조 | 주문 | 승인 전 금액 대조 (FR-607) |
| 결제 중복 승인 | 주문 | DB 유니크 제약 기반 멱등성 (FR-608) |
| 취약한 의존성 | 전체 | 추가 전 조회 (NFR-209) |

## CSRF

`net/http.CrossOriginProtection` (Go 1.25 표준 라이브러리)을 쓴다.
`gorilla/csrf`는 최신 v1.7.3에도 **수정 버전이 없는** CVE-2025-47909 대상이라 배제됐다 —
근거는 [DEC-2.1](../.ai/DECISIONS.md).

- 설치 트리와 운영 트리 **양쪽 모두**에 적용한다 (NFR-205)
- 토큰이 아니라 `Sec-Fetch-Site`/`Origin` 검사이므로 테마 템플릿에 히든 필드가 필요 없다.
  테마 작성자가 토큰을 빠뜨려 보호가 뚫리는 사고가 원천적으로 사라진다
- GET·HEAD·OPTIONS는 통과한다 → **안전 메서드로 상태를 바꾸지 말 것.**
  `GET /post/123/delete` 같은 라우트는 금지다

## 세션 (NFR-204)

| 항목 | 값 |
|---|---|
| 저장 | 서버측 (`scs` + `pgxstore`). 쿠키에는 식별자만 |
| `HttpOnly` | true |
| `SameSite` | Lax |
| `Secure` | TLS 사용 시 true. 설치 시 감지 후 설정 파일에 기록 |
| 수명 | 12시간 (조정 가능) |
| 로그인 시 | 세션 ID 재발급 (FR-204) |

## 비밀번호 (NFR-208)

- bcrypt (`golang.org/x/crypto/bcrypt`), 기본 cost
- 평문·MD5·SHA-1·솔트 없는 SHA-256 전부 금지
- 최소 길이 10자. 그 이상의 복잡도 규칙은 두지 않는다 — 규칙을 늘리면 운영자가
  더 약하고 예측 가능한 비밀번호를 만든다
- 로그인 실패 시 "이메일이 없음"과 "비밀번호가 틀림"을 구분해 알리지 않는다 (FR-201)

## SQL (NFR-202)

```go
// 옳음
pool.Query(ctx, "SELECT * FROM posts WHERE board_id = $1", boardID)

// 금지
pool.Query(ctx, "SELECT * FROM posts WHERE board_id = '"+boardID+"'")
```

정렬 컬럼처럼 바인딩할 수 없는 값은 **허용 목록**으로 검사한다. 이스케이프하지 않는다.

```go
var sortable = []string{"created_at", "view_count", "title"}
if !slices.Contains(sortable, col) { return errInvalidSort }
```

## 파일 업로드 (NFR-206)

네 가지를 **모두** 한다. 하나라도 빠지면 우회된다.

1. **확장자 허용 목록** — 차단 목록이 아니라 허용 목록. `.php5`, `.phtml`, `.svg` 같은 걸
   일일이 막을 수 없다
2. **MIME + 매직바이트 검증** — 클라이언트가 보낸 `Content-Type`을 믿지 않는다.
   `http.DetectContentType`으로 실제 내용을 본다. 확장자와 내용이 어긋나면 거부
3. **웹루트 밖 저장 + 파일명 재생성** — 원본 파일명은 표시용으로만 DB에 둔다.
   디스크에는 UUID 등으로 저장한다. 경로 순회(`../`)와 실행 가능 경로 배치를 동시에 막는다
4. **실행 권한 제거** — `0644`. 디렉터리에 실행 권한을 주지 않는다

SVG는 스크립트를 담을 수 있다. 허용한다면 정화하거나 `Content-Disposition: attachment`로만
서빙한다.

**이미지 허용 확장자는 `.jpg` `.jpeg` `.png` `.gif` `.webp` 다. `.svg`는 넣지 않는다** —
정화기를 유지하는 비용이 SVG 상품 이미지의 가치보다 크다. 필요해지면 그때
`Content-Disposition: attachment` 전용 서빙 경로와 함께 연다.

### 압축 해제 (테마 zip, FR-307)

아래를 **전부** 지킨다. 이 화면(A-203)이 최고 위험군인 이유는 업로드가 곧 **임의 파일 쓰기**이고,
쓰인 파일이 곧 **템플릿으로 실행**되기 때문이다.

| # | 방어 | 값·수단 |
|---|---|---|
| 1 | 상한 | 업로드 zip **20 MiB** / 해제 후 총 **20 MiB** · 엔트리 하나 **20 MiB** / 파일 수 **2,000** / 디렉터리 깊이 **10** / 압축비 **100:1** |
| 2 | 헤더 불신 | `zip.FileHeader.UncompressedSize64`는 **아카이브가 주장하는 값**이다. `io.LimitReader`로 감싸 **실제로 읽은 바이트**를 세다가 상한에서 중단한다 |
| 3 | 경로 봉쇄 | 대상 디렉터리를 `os.OpenRoot`로 열고 **모든 쓰기를 `os.Root` 메서드로만** 한다. 이름의 어느 구성요소든 루트 밖을 가리키면 `path escapes from parent` 오류가 난다 — 접두사 검사를 직접 짜지 않는다 (NFR-201) |
| 4 | 링크·특수 엔트리 거부 | `FileHeader.Mode()`에 `fs.ModeSymlink`가 있으면 거부. 정규 파일과 디렉터리가 아닌 엔트리는 전부 거부 |
| 5 | 원자 교체 | 임시 디렉터리에 풀고 **성공했을 때만** `rename`. 실패하면 임시 디렉터리를 통째로 지운다 — 설정 파일 쓰기와 같은 방식 ([D20](20-architecture.md)) |

> 상한 값의 근거는 NFR-101(1 vCPU / 512MB~1GB)이다. 해제 중 디스크·메모리를 그 티어가
> 감당해야 한다. 20 MiB는 [D17](17-theme-contract.md) 테마 구조에 넉넉하며, 넘겨야 하는
> 테마는 이미지가 테마 밖에 있어야 하는 테마다.
>
> 3번은 `os.Root`가 실제로 탈출을 거부하는 것을 확인하고 적었다 (2026-08-02, go1.25).

### 웹훅 본문 (P-905, FR-610)

본문 크기 상한 **64 KiB**. `http.MaxBytesReader`로 강제하고 초과는 413.
**서명 대상이 원문 바이트이므로 상한을 넘긴 본문은 서명 검증도 하지 않는다.**
NFR-101의 티어에서 무제한 본문 버퍼링은 그 자체가 DoS 표면이다.

## 연결 타임아웃 (NFR-101)

`http.Server`의 **네 타임아웃을 전부 설정한다.** 0은 무제한이다.

| 필드 | 값 | 막는 것 |
|---|---|---|
| `ReadHeaderTimeout` | 10s | 헤더를 한 글자씩 보내는 클라이언트 (Slowloris) |
| `ReadTimeout` | 30s | **헤더를 다 보낸 뒤 본문을 질질 끄는** 클라이언트 |
| `WriteTimeout` | 60s | 응답을 한 바이트씩 읽어 커넥션을 붙잡는 클라이언트. 우리가 서빙할 가장 큰 자산·첨부의 상한이기도 하다 |
| `IdleTimeout` | 120s | 조용해진 keep-alive 커넥션이 쌓이는 것 |

**`ReadHeaderTimeout` 하나만으로는 부족하다.** 헤더 이후는 전혀 보호되지 않는다.
1 vCPU / 512MB 인스턴스에서 이건 가장 값싼 서비스 거부이고, **프로세스 안의 어느 것도
알아채지 못하므로 테스트가 전부 통과하는 상태로 남는다.**

순서 불변식도 지킨다: `ReadHeaderTimeout ≤ ReadTimeout ≤ WriteTimeout ≤ IdleTimeout`.
`ReadTimeout`이 헤더 예산보다 짧으면 헤더 예산에 도달할 수 없다.
값과 순서 모두 `cmd/ondolith` 테스트가 고정하며, 필드를 하나라도 지우면 실패한다.

## 오류 메시지 (NFR-210)

- 사용자에게: 일반 메시지. 스택·쿼리·경로를 노출하지 않는다
- 로그에: 원인 전부
- **예외는 설치 마법사뿐이다.** 운영자가 유일한 청중이고, DB 접속 실패는 그들이 고쳐야
  하는 문제이므로 원문을 보여준다 (FR-107)

## 의존성 (NFR-209)

추가 전에:

```bash
go list -m -versions <module>
curl -s https://api.osv.dev/v1/query -d '{"package":{"name":"<module>","ecosystem":"Go"}}'
```

정기적으로:

```bash
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
```

이 절차를 빼먹어서 생긴 실수가 [M1](../.ai/MISTAKES.md)에 기록되어 있다.

## 배포 시 (→ [D70](70-operations.md))

- Lightsail에는 AWS WAF를 직접 붙일 수 없다. 결제를 다루므로 **CloudFront를 앞단에 두는
  구성**을 문서로 안내한다
- TLS는 리버스 프록시(Caddy 권장, 자동 인증서) 또는 CloudFront에서 종단한다
- 설정 파일·업로드 디렉터리를 백업에 포함하되 백업 자체를 공개 저장소에 두지 않는다

## 체크리스트 — 코드를 올리기 전

- [ ] 새 쿼리가 전부 파라미터 바인딩인가
- [ ] 새 `template.HTML` 사용처에 사유 주석이 있는가
- [ ] 새 상태 변경 라우트가 POST/PUT/DELETE인가 (GET이 아닌가)
- [ ] 새 업로드 경로가 4중 검증을 지키는가
- [ ] 새 의존성의 취약점을 조회했는가
- [ ] 오류 메시지가 내부 구조를 흘리지 않는가
