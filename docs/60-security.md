# D60. 보안

> 이 프로젝트에서 가장 위험한 영역이다. 그누보드가 20년간 반복해서 뚫린 지점이며,
> 새로 쓴 코드에는 그 20년치 경험이 없다. 요구사항: [D10](10-requirements.md) NFR-2xx.

## 첫 번째 규칙

**인증·세션·CSRF·업로드 검증을 자작하지 않는다** (NFR-201).

"우리 상황엔 간단한 걸로 충분하다"는 판단이 사고의 시작이다. 검증된 라이브러리를 쓴다.
지정 목록은 [.ai/DECISIONS.md](../.ai/DECISIONS.md) DEC-1.

## 위협 모델

배포형 제품이라 우리가 운영하지 않는 서버에서 돈다. 운영자는 보안 전문가가 아니다.

| 위협 | 대상 | 대응 |
|---|---|---|
| 미설치 서버 점유 | 설치 직후 창 | 설치를 빨리 끝내도록 안내. 부팅 시 경고 로그. CSRF는 설치 폼에도 적용 |
| 설정 파일 유출 | DB 비밀번호 | 파일 권한 0600. 웹루트 밖 |
| SQL 인젝션 | 게시판 검색·필터 | 파라미터 바인딩 강제 (NFR-202) |
| 저장형 XSS | 글·댓글 본문 | 기본 이스케이프. `template.HTML` 사용 시 사유 주석 (NFR-203) |
| 악성 파일 업로드 | 첨부·테마 | 4중 검증 (아래) |
| 세션 탈취·고정 | 로그인 | HttpOnly·SameSite·Secure, 로그인 시 ID 재발급 (FR-204) |
| 관리자 무차별 대입 | 로그인 | rate limiting (NFR-207) |
| 결제 금액 위변조 | 주문 | 승인 전 금액 대조 (FR-607) |
| 결제 중복 승인 | 주문 | DB 유니크 제약 기반 멱등성 (FR-608) |
| 취약한 의존성 | 전체 | 추가 전 조회 (NFR-209) |

## CSRF

`net/http.CrossOriginProtection` (Go 1.25 표준 라이브러리)을 쓴다.
`gorilla/csrf`는 최신 v1.7.3에도 **수정 버전이 없는** CVE-2025-47909 대상이라 배제됐다 —
근거는 [DEC-2.1](../.ai/DECISIONS.md).

- 설치 트리와 운영 트리 **양쪽 모두**에 적용한다 (NFR-205)
- 토큰이 아니라 `Sec-Fetch-Site`/`Origin` 검사이므로 테마 템플릿에 히든 필드가 필요 없다.
  테마 작성자가 토큰을 빠뜨려 보호가 뚫리는 사고가 원천적으로 사라진다
- GET·HEAD·OPTIONS는 통과한다 → **안전 메서드로 상태를 바꾸지 말 것.**
  `GET /post/123/delete` 같은 라우트는 금지다

**CSRF 검사는 클릭재킹을 막지 못한다.** 공격자가 이 사이트를 iframe에 넣고 위에
투명한 미끼를 얹으면, 사용자가 누르는 것은 이 사이트 안의 진짜 버튼이다 — 그 요청은
프레임 자신에게서 나오므로 `Sec-Fetch-Site: same-origin`이고 그대로 통과한다.
막는 것은 아래의 응답 헤더뿐이다.

## 응답 헤더 (NFR-211)

`internal/httpsec` 한 곳에 있고 **설치 트리와 운영 트리 양쪽**이 같은 것을 쓴다.
두 벌로 적으면 한쪽만 고쳐진다 — 설치 화면은 DB 비밀번호를 받는 폼이라
클릭재킹의 대가가 더 크지, 덜하지 않다.

| 헤더 | 값 | 막는 것 |
|---|---|---|
| `X-Frame-Options` | `DENY` | 클릭재킹. CSP를 모르는 브라우저용 |
| `Content-Security-Policy` | `frame-ancestors 'none'; object-src 'none'; base-uri 'self'; form-action 'self'` | 클릭재킹 · 플러그인 · `<base>` 주입 · 폼이 남의 서버로 제출되는 것 |
| `X-Content-Type-Options` | `nosniff` | 브라우저가 타입을 다시 추측하는 것 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 재설정 토큰(`/password/reset/{토큰}`)이 `Referer`로 새는 것 |

**`script-src`·`style-src`는 잠그지 않았다.** 테마가 인라인 스타일과 `onsubmit`
확인창을 쓰고, 그것을 막으려면 테마 작성자마다 nonce를 다뤄야 한다 — 재컴파일 없이
테마를 갈아 끼운다는 전제([DEC-3.1](../.ai/DECISIONS.md))와 맞지 않는다. `default-src`도
두지 않는다: 테마가 외부 폰트나 이미지를 쓰는 것은 정상 사용이고, 여기서 막으면
테마가 깨진 채로 배포된다. XSS의 1차 방어는 `html/template`의 자동 이스케이프이고
(NFR-203), CSP는 그것이 뚫렸을 때의 두 번째 문이다.

## 세션 (NFR-204)

| 항목 | 값 |
|---|---|
| 저장 | 서버측 (`scs` + `pgxstore`). 쿠키에는 식별자만 |
| `HttpOnly` | true |
| `SameSite` | Lax |
| `Secure` | TLS 사용 시 true. 설치 시 감지 후 설정 파일에 기록 |
| 수명 | 12시간 (조정 가능) |
| 로그인 시 | 세션 ID 재발급 (FR-204) |

## 비밀번호 (NFR-208)

- bcrypt (`golang.org/x/crypto/bcrypt`), 기본 cost
- 평문·MD5·SHA-1·솔트 없는 SHA-256 전부 금지
- 최소 길이 10자. 그 이상의 복잡도 규칙은 두지 않는다 — 규칙을 늘리면 운영자가
  더 약하고 예측 가능한 비밀번호를 만든다
- 로그인 실패 시 "이메일이 없음"과 "비밀번호가 틀림"을 구분해 알리지 않는다 (FR-201)

## SQL (NFR-202)

```go
// 옳음
pool.Query(ctx, "SELECT * FROM posts WHERE board_id = $1", boardID)

// 금지
pool.Query(ctx, "SELECT * FROM posts WHERE board_id = '"+boardID+"'")
```

정렬 컬럼처럼 바인딩할 수 없는 값은 **허용 목록**으로 검사한다. 이스케이프하지 않는다.

```go
var sortable = []string{"created_at", "view_count", "title"}
if !slices.Contains(sortable, col) { return errInvalidSort }
```

## 파일 업로드 (NFR-206)

네 가지를 **모두** 한다. 하나라도 빠지면 우회된다.

1. **확장자 허용 목록** — 차단 목록이 아니라 허용 목록. `.php5`, `.phtml`, `.svg` 같은 걸
   일일이 막을 수 없다
2. **MIME + 매직바이트 검증** — 클라이언트가 보낸 `Content-Type`을 믿지 않는다.
   `http.DetectContentType`으로 실제 내용을 본다. 확장자와 내용이 어긋나면 거부
3. **웹루트 밖 저장 + 파일명 재생성** — 원본 파일명은 표시용으로만 DB에 둔다.
   디스크에는 UUID 등으로 저장한다. 경로 순회(`../`)와 실행 가능 경로 배치를 동시에 막는다
4. **실행 권한 제거** — `0644`. 디렉터리에 실행 권한을 주지 않는다

SVG는 스크립트를 담을 수 있다. 허용한다면 정화하거나 `Content-Disposition: attachment`로만
서빙한다.

**이미지 허용 확장자는 `.jpg` `.jpeg` `.png` `.gif` `.webp` 다. `.svg`는 넣지 않는다** —
정화기를 유지하는 비용이 SVG 상품 이미지의 가치보다 크다. 필요해지면 그때
`Content-Disposition: attachment` 전용 서빙 경로와 함께 연다.

**상품 이미지(A-502)는 첨부와 같은 검증기를 지난다** (`content.StoreUpload`) — 허용목록을 위
다섯 확장자로 **좁혀서** 부를 뿐 네 겹을 다시 쓰지 않는다. 저장 위치도 같은 업로드 루트다
(테마·정적 자산 트리가 아니다). 서빙(P-306)은 `inline`인데, 그래도 되는 근거가 이 좁힌
허용목록이므로 `product_images.mime_type`의 `CHECK`가 같은 집합을 DB에서 한 번 더 막는다
([D30](30-data-model.md)).

### 첨부 상한 (A-309)

**파일당 크기와 글당 개수는 설정값이다** (`upload.max_bytes` 기본 20 MiB,
`upload.max_per_post` 기본 10). 상한이 없으면 글 하나가 디스크를 다 쓴다.
값이 이상하면 기본값으로 물러서지 않고 **거부한다** — 0을 적어 둔 사이트가
조용히 20 MiB를 허용하면 운영자는 자기가 정한 값이 걸려 있다고 믿는다.

**확장자는 뺄 수만 있다** (`upload.deny_ext`). 내장 허용목록에 더하는 설정은
두지 않는다 — 자유 목록이면 위에서 뺀 `.svg`가 폼 한 칸으로 돌아오고, 그때
함께 열기로 한 첨부 전용 서빙 경로가 무효가 된다. 더하는 것은 코드 변경이다.

### 압축 해제 (테마 zip, FR-307)

아래를 **전부** 지킨다. 이 화면(A-203)이 최고 위험군인 이유는 업로드가 곧 **임의 파일 쓰기**이고,
쓰인 파일이 곧 **템플릿으로 실행**되기 때문이다.

| # | 방어 | 값·수단 |
|---|---|---|
| 1 | 상한 | 업로드 zip **20 MiB** / 해제 후 총 **20 MiB** · 엔트리 하나 **20 MiB** / 파일 수 **2,000** / 디렉터리 깊이 **10** / 압축비 **100:1** |
| 2 | 헤더 불신 | `zip.FileHeader.UncompressedSize64`는 **아카이브가 주장하는 값**이다. `io.LimitReader`로 감싸 **실제로 읽은 바이트**를 세다가 상한에서 중단한다 |
| 3 | 경로 봉쇄 | 대상 디렉터리를 `os.OpenRoot`로 열고 **모든 쓰기를 `os.Root` 메서드로만** 한다. 이름의 어느 구성요소든 루트 밖을 가리키면 `path escapes from parent` 오류가 난다 — 접두사 검사를 직접 짜지 않는다 (NFR-201) |
| 4 | 링크·특수 엔트리 거부 | `FileHeader.Mode()`에 `fs.ModeSymlink`가 있으면 거부. 정규 파일과 디렉터리가 아닌 엔트리는 전부 거부 |
| 5 | 원자 교체 | 임시 디렉터리에 풀고 **성공했을 때만** `rename`. 실패하면 임시 디렉터리를 통째로 지운다 — 설정 파일 쓰기와 같은 방식 ([D20](20-architecture.md)) |

> 상한 값의 근거는 NFR-101(1 vCPU / 512MB~1GB)이다. 해제 중 디스크·메모리를 그 티어가
> 감당해야 한다. 20 MiB는 [D17](17-theme-contract.md) 테마 구조에 넉넉하며, 넘겨야 하는
> 테마는 이미지가 테마 밖에 있어야 하는 테마다.
>
> 3번은 `os.Root`가 실제로 탈출을 거부하는 것을 확인하고 적었다 (2026-08-02, go1.25).

### 웹훅 본문 (P-905, FR-610)

본문 크기 상한 **64 KiB** (`internal/app/handler_webhook.go`의 `maxWebhookBody`, 2026-10-07 에 1 MiB 에서 줄임). 이 주소는 인증이 없고 형태만 맞으면 원문이 `webhook_events` 에 남으므로 상한이 곧 요청 하나가 쌓는 양이다. A-603 은 원문을 앞 4,096자만 읽는다.
`http.MaxBytesReader`로 강제하고 초과는 413.
NFR-101의 티어에서 무제한 본문 버퍼링은 그 자체가 DoS 표면이다.

**토스페이먼츠 웹훅에는 서명이 없다** (2026-08-05 공식 문서 확인, [D50](50-commerce.md)).
이 절은 원래 "서명 대상이 원문 바이트이므로 상한을 넘긴 본문은 서명 검증도 하지 않는다"고
적고 있었는데, 검증할 서명이 없다. 실제 수단은 본문 `secret` 과 승인 응답 `secret` 의 대조
하나이고, 그것은 값을 아는 쪽이면 흉내낼 수 있다 — 그래서 **웹훅은 신호로만 쓰고 상태는
조회 API로 확인한다** (D15 SC-8 2~3항).

## 리치 텍스트 본문 (FR-513)

에디터가 만든 HTML 은 **브라우저가 보낸 값**이다 — 에디터를 거쳤다는 보장이 없다. 그래서
저장 전에 허용목록 정화를 지나고(`internal/content/richtext.go`, bluemonday v1.0.27 의 UGC
정책에서 출발), **그릴 때 한 번 더** 지난다 — 정책을 좁힌 뒤에도 예전에 저장된 HTML 이
예전 정책으로 나가지 않게.

| 남는 것 | 빠지는 것 |
|---|---|
| 문단·제목·목록·인용·표·굵게/기울임/밑줄/취소선·링크(http·https·mailto·tel, 외부 링크는 `rel="nofollow noopener"`·새 창) | `script`·`style`·`svg`·`object`·`form`·`meta`·`base`, 모든 `on*` 속성, `javascript:`·`data:` 주소 |
| 인라인 스타일 중 색(`#hex`·`rgb()`)·정렬(4값)·글자 크기·크기(px·%) — **값까지** 검사 | 그 밖의 스타일(`url(`·`expression(` 이 들어갈 자리가 없다), `class`(사이트의 클래스로 화면을 흉내 낼 수 있다) |
| `iframe` — `https://www.youtube(-nocookie).com/embed/…`·`https://www.google.com/maps/embed?pb=…` 만, `sandbox` 를 붙여서 | 그 밖의 iframe 은 요소째 |

평문(`body`)은 정화된 HTML 에서 글자만 뽑은 것이다 — 블록이 끝나면 줄을 바꾸고 엔티티를
글자로 돌린다. 검색(`search_vector`)이 태그를 색인하지 않게 하려는 것이다.

## 공개 폼 스팸 방지 (FR-216)

가입(P-103)·재설정 요청(P-104)·새 글(P-205)·새 댓글(P-208)은 저장 전에 `spamGuard` 를 지난다
(`internal/app/spam.go`).

| 규칙 | 이유 |
|---|---|
| 숨은 칸 `website-url` 은 늘 켜져 있다. 채워 오면 422, 저장하지 않는다 | 폼을 읽지 않고 칸마다 값을 넣는 프로그램을 바깥 호출 없이 거른다. 이름에 하이픈이 있어 커스텀 필드 키(`^[a-z][a-z0-9_]*$`)와 겹치지 않는다 |
| Turnstile 은 A-201 에 사이트 키와 비밀 키가 **둘 다** 있을 때만 켜진다 | 위젯(`.Site.Turnstile`)과 서버 검사가 같은 조건을 봐야 「위젯은 없는데 토큰을 요구한다」가 생기지 않는다. 키가 없으면 바깥 호출도 없다 |
| 토큰은 서버가 siteverify 로 확인한다 (`auth.Turnstile`). 빈 토큰·2048자 초과는 묻지 않고 거부 | 토큰은 5분·1회용이다(Cloudflare 문서). 위젯이 만료 토큰을 스스로 갱신한다(`refresh-expired=auto` 기본값) |
| siteverify 의 `invalid-input-secret` 등 우리 쪽 오류와 불통은 502 + 로그, 저장하지 않는다 | 방문자에게 「자동 입력」 이라 하면 운영자는 모든 가입이 막힌 이유를 모른다. 열린 쪽으로 실패하면 Cloudflare 가 느린 동안 스팸이 그대로 들어온다 |
| 가입은 비밀번호 해시 **전에** 본다 | 봇의 제출마다 해시 비용을 치르지 않는다 |
| 글·댓글은 다른 검증을 다 지난 **뒤에** 본다 | 바깥 호출과 1회용 토큰을, 어차피 거부될 제출에 쓰지 않는다 |

확인한 것: 2026-10-08 Cloudflare 문서의 시험용 비밀 키 세 개(항상 통과·항상 실패·이미 쓴 토큰)와 엉터리 키를 실제
siteverify 에 보내, 각각 통과·거부·거부·우리 쪽 오류로 읽히는 것을 봤다. **사람이 실제 위젯을 푸는 흐름은 자동
시험에 없다** — 통합 시험은 위젯이 그려지는 것과 토큰 없는 제출이 거부되는 것까지 본다 ([D85](85-gaps.md) GAP-27).

## 백업 내려받기 (A-604, FR-713)

| 규칙 | 이유 |
|---|---|
| 최고 관리자 + 비밀번호 재확인, 받으면 작업 로그 | 덤프에 모든 회원의 비밀번호 해시와 봉인된 자격증명이 있다 |
| `sessions` 표의 **데이터**는 덤프에서 뺀다 (`--exclude-table-data`) | 파일이 새면 그 안의 세션 토큰으로 지금 사이트에 그 사람으로 들어갈 수 있다 |
| 설정 파일을 넣지 않는다 | `secret_key` 가 같이 있으면 덤프의 봉인된 PG·SMTP·소셜·Turnstile 키가 풀린다 |
| DB 비밀번호는 `PGPASSWORD` 환경으로 넘긴다 | `pg_dump` 의 인자는 `/proc/<pid>/cmdline` 으로 같은 서버의 모든 계정에 보인다. 설치가 쓰는 URL DSN 에서만 떼어 낸다 — key=value DSN 은 그대로 넘긴다(알려진 한계) |
| 업로드 폴더는 `os.Root` 로 걷는다 | 폴더 밖을 가리키는 심볼릭 링크를 따라 서버의 다른 파일을 싣지 않는다 |
| 덤프를 끝까지 받은 뒤에 응답을 시작한다 | 중간에 실패하면 200 과 잘린 zip 이 나가고, 사람은 그것을 백업으로 믿는다 |
| 자동 백업(FR-715) 폴더는 0700, 파일은 0600 | 같은 내용이 디스크에 남는다. 서버의 다른 계정이 읽으면 회원 비밀번호 해시가 나간다 |
| 저장된 백업은 이름 모양(`auto-YYYYMMDD-HHMM.zip`)을 보고 `os.Root` 로 연다 | 폼의 `name` 이 경로 조각이면 서버의 다른 파일을 내려받는 길이 된다 |
| 백업 폴더가 업로드 폴더 안이면 기동을 거부한다 | 업로드 폴더는 백업에 통째로 들어간다 — 다음 백업이 이전 백업을 싣고 하루마다 커져 디스크를 채운다 |
| 자동 백업은 임시 파일에 다 쓴 뒤에만 이름을 붙이고, 실패한 날은 다시 시도하지 않는다 | 잘린 백업이 목록에 오르지 않고, 실패가 이전 백업을 밀어내지 않는다. 매분 실패하는 pg_dump 가 로그를 덮지 않는다 |

## 연결 타임아웃 (NFR-101)

`http.Server`의 **네 타임아웃을 전부 설정한다.** 0은 무제한이다.

| 필드 | 값 | 막는 것 |
|---|---|---|
| `ReadHeaderTimeout` | 10s | 헤더를 한 글자씩 보내는 클라이언트 (Slowloris) |
| `ReadTimeout` | 30s | **헤더를 다 보낸 뒤 본문을 질질 끄는** 클라이언트 |
| `WriteTimeout` | 60s | 응답을 한 바이트씩 읽어 커넥션을 붙잡는 클라이언트. 우리가 서빙할 가장 큰 자산·첨부의 상한이기도 하다 |
| `IdleTimeout` | 120s | 조용해진 keep-alive 커넥션이 쌓이는 것 |

**`ReadHeaderTimeout` 하나만으로는 부족하다.** 헤더 이후는 전혀 보호되지 않는다.
1 vCPU / 512MB 인스턴스에서 이건 가장 값싼 서비스 거부이고, **프로세스 안의 어느 것도
알아채지 못하므로 테스트가 전부 통과하는 상태로 남는다.**

순서 불변식도 지킨다: `ReadHeaderTimeout ≤ ReadTimeout ≤ WriteTimeout ≤ IdleTimeout`.
`ReadTimeout`이 헤더 예산보다 짧으면 헤더 예산에 도달할 수 없다.
값과 순서 모두 `cmd/ondolith` 테스트가 고정하며, 필드를 하나라도 지우면 실패한다.

## 저장된 자격증명 (A-201 · A-205 · A-206 · A-209)

운영자가 관리자 화면에 넣는 **PG 시크릿 키·SMTP 비밀번호·소셜 client_secret·Turnstile 비밀 키** 는
`settings` 에 **봉인해서** 둔다 (`internal/secretbox`, AES-256-GCM). 봉인 키는
`ondolith.json` 의 `secret_key` 다 — DSN 과 같은 파일, 같은 0600.

| 규칙 | 이유 |
|---|---|
| 키는 DB 에 두지 않는다 | DB 가 지키려는 대상이다. 덤프 한 장이 새면 `pg.secret_key` 로 상점의 모든 승인·취소를 남이 부를 수 있었다 |
| 키는 관리자가 입력하지 않는다 | 입력받은 키도 어딘가에 저장해야 하고 후보는 DB 뿐이다. 매 부팅 입력은 재시작을 사람에게 묶는다. 설치가 만들고 파일에 둔다 |
| 설정 키 이름이 AAD 다 | 봉인된 값을 다른 설정 자리로 옮겨 붙여도 열리지 않는다 |
| 어떤 자격증명이 시크릿인지는 **한 곳**(`content.IsSecretSetting`) | 화면이 다시 보여주지 않는 목록과 봉인하는 목록이 같아야 한다 |
| 열리지 않는 값은 오류다 | 평문인 척 돌려주면 그 시크릿으로 PG 를 불러 엉뚱한 실패가 난다. 키가 바뀐 설정 파일로 부팅한 것이고, 오류가 그렇게 말한다 |
| 봉인 전에 저장된 값(v0.1.0·v0.2.0)은 부팅 때 봉인한다 | 평문 행이 남아 있으면 그 뒤의 백업이 평문을 담는다 |

`make test-toss` 의 테스트 키는 이 경로가 아니다 — 환경변수로만 받고 저장하지 않는다
([D73](73-toss-verification.md)).

## SMTP 호스트 (A-205)

**`169.254.0.0/16` 만 거부한다.** 클라우드 메타데이터가 응답하는 대역이다
(`169.254.169.254`). 사설·루프백 릴레이는 메일을 운영하는 정상적인 방식이라 막지
않는다 — 막으면 지키는 것보다 깨뜨리는 사이트가 많다.

**판정은 DNS 해석 뒤·connect 직전에 한다** (`net.Dialer.Control`). 저장 시점에
호스트 문자열만 보는 검사는 저장한 뒤 그 이름을 `169.254.169.254` 로 돌리면
그만이다 — 그 검사는 안전을 주지 않으면서 안전해 보이게 만든다.

**저장한 TLS 모드를 발송에도 적용한다.** `starttls`는 서버의 STARTTLS 지원이 없으면
중단하고, `tls`는 접속 직후 인증서를 검증한 다음 SMTP 교환을 시작한다. 모드가
비어 있으면 STARTTLS를 사용한다. 평문 로컬 릴레이는 `none`을 명시한다.
기본 포트는 TLS가 465, 나머지가 587이다. 교환 전체는 최대 30초이며 호출자
시한이 더 짧으면 그쪽을 따른다. 접속 후 요청이 취소돼도 연결을 닫는다.
