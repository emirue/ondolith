# D22. 개발 규약

**어떻게 만드는가의 단일 출처다.** 무엇으로 만드는가는 [D21](21-tech-stack.md),
구조는 [D20](20-architecture.md), 문서 규칙은 [D90](90-conventions.md).

---

## 1. 패키지 구조와 경계

```
cmd/ondolith/        main. 플래그, 부팅 분기, 핸들러 교체, graceful shutdown
internal/
  config/            설정 파일 읽기·쓰기
  install/           설치 트리
  app/               운영 트리 조립
  migrations/        goose 마이그레이션 (embed.FS)
```

Phase 1 이후 추가될 자리는 [D20](20-architecture.md)에 있다.

| 규칙 | 내용 |
|---|---|
| `internal/` 밖으로 내보내지 않는다 | 이 저장소는 라이브러리가 아니라 제품이다 |
| 패키지는 **도메인**으로 나눈다 | `handlers/`, `models/`, `utils/` 같은 **역할별 분할 금지** — 기능 하나를 고치는 데 세 디렉터리를 오가게 된다 |
| 순환 참조 금지 | `go build`가 막지만, 막히면 경계를 잘못 그은 것이다 |
| `utils`·`common`·`helpers` 금지 | 이름이 아무것도 설명하지 않는 패키지는 쓰레기통이 된다 |

## 2. 코딩 표준

`gofmt`가 형식을 정한다. 그 위에 얹는 것만 적는다.

| 항목 | 규칙 |
|---|---|
| 주석 언어 | **코드 주석은 영어, 문서는 한국어.** 주석은 코드를 읽는 사람이 보고, 문서는 기획을 읽는 사람이 본다 |
| 주석 내용 | **무엇을 하는지가 아니라 왜 그런지**를 적는다. `// increment i` 금지 |
| 이름 | Go 관례를 따른다. 약어는 대문자 유지 (`ID`, `URL`, `DSN`) |
| 파일 길이 | 상한을 두지 않는다. 한 파일이 커지면 그건 경계 문제이지 줄 수 문제가 아니다 |
| 전역 변수 | 금지. 예외는 `embed.FS`와 `-ldflags`로 주입되는 `version` |
| `init()` | 금지. 초기화 순서가 보이지 않는다 |
| 의도적 단순화 | `// ponytail:` 주석으로 **한계와 승급 경로**를 함께 적는다 |

## 3. 오류 처리

| 규칙 | 내용 |
|---|---|
| 감싸기 | `fmt.Errorf("맥락: %w", err)`. **맥락은 호출자가 모르는 것**을 적는다 — `"failed to"` 같은 말은 정보가 아니다 |
| 판별 | `errors.Is` / `errors.As`. 문자열 비교 금지 |
| 센티널 | 호출자가 분기해야 하는 것만 만든다 (`config.ErrNotInstalled`) |
| 삼키기 | 금지. 무시할 거면 `_ = f()`로 **의도를 보이게** 한다 |
| 패닉 | 라이브러리 코드에서 금지. `main`의 기동 실패만 예외이며 그마저 `os.Exit(1)`을 쓴다 |

**사용자에게 보이는 오류와 로그는 다르다** (NFR-210).

| 대상 | 내용 |
|---|---|
| 사용자 | 일반 메시지. 스택·쿼리·경로 없음 |
| 로그 | 원인 전부 |
| **예외** | 설치 마법사(P-001)만 원문을 보여준다. 운영자가 유일한 청중이고 그들이 고쳐야 할 문제다 (FR-107) |

## 4. 로깅

`log/slog`, 구조화 로깅. `fmt.Println` 금지.

| 레벨 | 쓰는 때 |
|---|---|
| `Error` | 요청이 실패했고 원인을 남겨야 한다 |
| `Warn` | 진행은 됐지만 운영자가 알아야 한다 (설치 전 상태, 종료 데드라인 초과) |
| `Info` | 기동·종료·설치 완료 같은 생애주기 사건 |
| `Debug` | 개발 모드에서만 |

**로그에 절대 넣지 않는 것** — 비밀번호·해시, 세션 토큰, 카드정보, PG 시크릿,
재설정·인증 토큰 원문, **DSN**([D15](15-access-control.md) 7절).

> DSN을 로그에 넣지 않는 것은 규칙이 아니라 사고 이력이다. 테마 뷰모델에 설정 구조체를
> 통째로 넘겨 DB 비밀번호가 템플릿에 노출될 뻔했다. **비밀을 담은 값은 전달 범위를 좁힌다.**

## 5. 동시성

| 규칙 | 내용 |
|---|---|
| 공유 상태 | 기본은 공유하지 않기. 필요하면 `atomic` 또는 뮤텍스 |
| **원자적으로 보호한 값 옆에 비보호 값을 두지 않는다** | 생명주기를 함께하는 것은 같은 단위에 넣는다 ([M5](../.ai/MISTAKES.md)) |
| 정리는 멱등하게 | `sync.Once`. 두 경로에서 도달할 수 있으면 반드시 |
| 불변식은 DB로 | 애플리케이션 검사만으로는 동시 요청을 막지 못한다 — 유니크 제약·`FOR UPDATE` (FR-608, FR-611, [D15](15-access-control.md) 5.2) |
| 테스트 | `go test -race`가 기본이다. 동시성 수정에는 **옛 설계를 복원해 `-race`가 잡는지** 확인하는 회귀 테스트를 남긴다 |

## 6. SQL

| 규칙 | 내용 |
|---|---|
| 바인딩 | **항상 파라미터 바인딩.** 문자열 연결 금지 (NFR-202) |
| 바인딩 불가한 값 | 정렬 컬럼 같은 것은 **허용 목록**으로 검사한다. 이스케이프하지 않는다 |
| 소유권 | `WHERE`에 넣는다. 조회 후 Go에서 비교하지 않는다 ([D15](15-access-control.md) P4) |
| N+1 | 목록 조회는 상수 개수의 쿼리여야 한다 (NFR-105) |
| 트랜잭션 | 여러 행의 불변식이 걸린 작업은 트랜잭션 안에서. `defer tx.Rollback(ctx)`를 먼저 건다 |
| 마이그레이션 | 규칙은 [D30](30-data-model.md). 모든 파일에 `-- +goose Down` (NFR-303) |

## 7. 테스트 전략

**층위마다 무엇을 검증하는지가 다르다.** 아래 표가 "이건 어디서 테스트하지"의 답이다.

| 층위 | 대상 | DB | 명령 |
|---|---|---|---|
| **단위** | 순수 판단 로직 — 검증 규칙, 포맷, 상태 전이, 권한 판정 | 불필요 | `make test` |
| **패키지 내 통합** | 미들웨어 체인, 템플릿 렌더링, 핸들러 + `httptest` | 불필요 | `make test` |
| **DB 통합** | 마이그레이션, 제약, 트랜잭션, 설치 흐름 | 필요 | `make test-integration` |
| **문서 정합성** | ID 상호참조, 커버리지, 어휘 | — | `make check`의 `docs` |
| **도구 자체** | 검사 스크립트가 위반을 실제로 잡는가 | — | `make check`의 `selftest` |

### 규칙

| # | 규칙 |
|---|---|
| 1 | **비자명한 로직에 테스트를 하나 남긴다** (NFR-405). 분기·루프·파서·금액/보안 경로. 자명한 한 줄은 두지 않는다 |
| 2 | **DB가 필요하면 그건 설계 신호다.** 판단 로직을 순수 함수로 분리하면 단위 테스트가 된다 ([M4](../.ai/MISTAKES.md)) |
| 3 | **테스트를 쓴 뒤 대상 코드를 고장내 실패하는지 확인한다.** 통과는 "테스트가 있다"이지 "테스트가 문다"가 아니다 |
| 4 | 단언은 값별로 나눈다. 뭉치면 어느 것이 깨졌는지 모른다 |
| 5 | **`[no test files]`는 통과가 아니라 정보 없음이다** ([M7](../.ai/MISTAKES.md)) |
| 6 | 테스트를 이름으로 고르지 않는다. 다 돌린 뒤 **무엇이 실제로 돌았는지** 확인한다 ([M6](../.ai/MISTAKES.md)) |
| 7 | 통과시키려고 단언을 지우거나 약화하지 않는다. 실패는 정보다 |

### 쓰지 않는 것

| 안 쓰는 것 | 이유 |
|---|---|
| 목(mock) 프레임워크 | 인터페이스와 작은 페이크로 충분하다. 목은 구현을 테스트에 새긴다 |
| 어서션 라이브러리 | `if got != want { t.Errorf }`로 족하다. 의존성 하나를 줄인다 |
| 테스트 픽스처 프레임워크 | 헬퍼 함수로 충분하다 |

## 8. 품질 게이트

```bash
make check     # build · vet · gofmt · test(-race) · docs · selftest
```

**완료 선언 전 필수다** (NFR-404). 통과하지 않은 것을 "됐다"고 말하지 않는다.

| 단계 | 무엇을 막나 |
|---|---|
| `build` | 컴파일 오류 |
| `vet` | 정적 분석이 잡는 실수 |
| `fmt` | 형식 논쟁 |
| `test` | `-race` 포함. 경합도 여기서 잡힌다 |
| `docs` | 문서 규칙 26종 ([D90](90-conventions.md) 9절) |
| `selftest` | **검사 도구가 위반을 실제로 잡는지** |

`make vuln`은 네트워크가 필요해 게이트에 없다. **릴리즈 전 필수**다 ([D21](21-tech-stack.md) 1절).

## 9. 구현 순서

각 Phase 안에서 이 순서로 만든다. **아래가 위를 필요로 하므로 뒤집으면 되돌아온다.**

| 순서 | 무엇 | 왜 먼저 |
|---|---|---|
| 1 | 마이그레이션 | 스키마 없이는 아무것도 검증할 수 없다 |
| 2 | 도메인 타입·순수 로직 | DB 없이 테스트되는 부분을 먼저 굳힌다 |
| 3 | 저장소 접근 (쿼리) | 통합 테스트 대상 |
| 4 | 권한 판정 | 핸들러가 이걸 부른다 |
| 5 | 핸들러 | 라우트 등록 시 권한을 함께 선언한다 ([D15](15-access-control.md) 4.4) |
| 6 | 템플릿·뷰 모델 | **뷰 모델은 필요한 필드만 담는다** ([D17](17-theme-contract.md)) |
| 7 | 관리자 화면 | 공개 화면이 소비할 데이터를 만드는 쪽 |

**화면 하나를 만들 때의 체크리스트**

1. [D11](11-screens.md)에서 `접근`·`상태변경`·`유형` 확인
2. `유형`에 해당하는 [D15](15-access-control.md) 6절 체크리스트를 읽는다
3. [D12](12-screens-public.md)/[D13](13-screens-admin.md)의 상세에서 **입력에 없는 필드는 받지 않는다**
4. 템플릿 이름은 [D17](17-theme-contract.md)에서 확인
5. `make check`

## 10. 커밋

| 규칙 | 내용 |
|---|---|
| 브랜치 | 기능 브랜치. `main`에서 직접 작업하지 않는다 |
| 메시지 | `영역: 무엇을 했는가 (FR-###)`. 예: `install: 관리자 계정 생성 (FR-104)` |
| 단위 | 하나의 커밋은 하나의 변경. `make check`가 통과하는 상태로 커밋한다 |
| 문서 | 코드와 **같은 커밋**에서 갱신한다. 나중에 하면 안 한다 |
