# D10. 기획 문서 — 요구사항 명세

이 문서가 "무엇을 만드는가"의 단일 출처다. 코드·커밋·이슈는 여기의 ID를 인용한다.

**읽는 법**

- `FR-###` 기능 요구사항 / `NFR-###` 비기능 요구사항
- **필수** = 해당 Phase 완료 조건. **선택** = 여유가 있으면.
- 각 항목의 "완료 기준"은 검증 가능하게 쓴다. "잘 동작한다"는 완료 기준이 아니다.

| 대역 | 영역 | 주 Phase |
|---|---|---|
| FR-1xx | 설치 | 0 |
| FR-2xx | 인증·세션·권한 | 1 |
| FR-3xx | 테마 | 1 |
| FR-4xx | 페이지 | 1 |
| FR-5xx | 게시판 | 2 |
| FR-6xx | 커머스·결제 | 3 |
| FR-7xx | 관리자 | 1~3 |
| NFR-1xx | 성능·자원 | 전체 |
| NFR-2xx | 보안 | 전체 |
| NFR-3xx | 배포·패치 | 0, 4 |
| NFR-4xx | 확장성·유지보수 | 전체 |

## FR-1xx 설치

> 그누보드와 같은 경험이 목표다. 터미널을 열지 않고 브라우저에서 끝난다.
> 이 구조는 **프로젝트 초기에** 잡아야 한다. 나중에 얹으면 라우팅 전체를 뜯게 된다.

| ID | 요구사항 | 우선 | Phase | 완료 기준 |
|---|---|---|---|---|
| FR-101 | 미설치 상태로 기동하면 모든 요청이 `/install`로 유도된다 | 필수 | 0 | 설정 파일이 없을 때 `/`, `/admin`, `/아무거나` → `303 → /install` |
| FR-102 | 설치 폼에서 DB 접속정보·관리자 계정·사이트 이름을 받는다 | 필수 | 0 | 폼 제출 한 번으로 설치가 끝난다 |
| FR-103 | 마이그레이션은 바이너리에 내장되어 자동 실행된다 | 필수 | 0 | 별도 CLI 실행 단계가 없다 (`embed.FS` + goose) |
| FR-104 | 첫 관리자 계정을 생성한다 | 필수 | 0 | 비밀번호는 bcrypt 해시로만 저장된다 |
| FR-105 | 설정 파일을 기록하고 설치 완료로 표시한다 | 필수 | 0 | 파일 권한 `0600`. DB 비밀번호가 들어 있다 |
| FR-106 | 설치 후 재시작 없이 운영 모드로 전환된다 | 필수 | 0 | 설치 완료 직후 `/`가 사이트를 반환한다 |
| FR-107 | 설치 실패 시 원인을 사용자에게 그대로 보여준다 | 필수 | 0 | DB 접속 실패·권한 부족 메시지가 화면에 나온다 |
| FR-108 | 이미 사용 중인 DB에 덮어쓰지 않는다 | 필수 | 0 | 같은 이메일의 계정이 있으면 거부하고 안내한다 |
| FR-109 | 설치 마법사가 콘솔 토큰을 요구하지 않는다 | 필수 | 0 | [DEC-3.3](../.ai/DECISIONS.md) — PocketBase 방식 배제 근거 |
| FR-110 | 설정 파일이 깨졌을 때 설치 모드로 되돌아가지 않는다 | 필수 | 0 | 파싱 실패 시 기동 중단. 지나가는 사람이 사이트를 재점유할 수 없다 |

**핵심 설계 원칙:** 설치 전과 설치 후는 **완전히 다른 라우트 트리**를 갖는다. 하나의 라우터에
조건 분기를 넣지 말고, 기동 시점에 어느 트리를 등록할지 결정한다. ([D20](20-architecture.md))

## FR-2xx 인증·세션·권한

| ID | 요구사항 | 우선 | Phase | 완료 기준 |
|---|---|---|---|---|
| FR-201 | 이메일+비밀번호 로그인 | 필수 | 1 | 실패 시 사유를 구분해 알려주지 않는다(계정 열거 방지) |
| FR-202 | 서버측 세션 (`scs` + `pgxstore`) | 필수 | 1 | 세션 쿠키에 식별자만. 상태는 DB |
| FR-203 | 로그아웃 시 세션을 파기한다 | 필수 | 1 | DB의 세션 행이 사라진다 |
| FR-204 | 로그인 시 세션 ID를 재발급한다 | 필수 | 1 | 세션 고정 공격 방어 |
| FR-205 | 역할 기반 접근 제어(RBAC) | 필수 | 1 | 역할–권한–사용자 3테이블. 게시판별 권한이 표현된다 |
| FR-206 | ~~회원 레벨 개념 병행~~ | 폐기 | – | **요구사항이 아니라 결정 사항이었다.** "얹을 수 있는지 결론"은 완료 기준이 될 수 없다 → **결론: 얹지 않는다** ([D15](15-access-control.md) 7-1절). 도입하기로 정하면 새 번호로 요구사항을 만든다 (번호 재사용 금지) |
| FR-207 | 비밀번호 재설정 (이메일) | 선택 | 1 | 일회용 토큰, 만료 있음 |
| FR-208 | 소셜 로그인 (`goth`) | 선택 | 1 | 최소 1개 프로바이더 |
| FR-209 | 관리자 경로 rate limiting | 필수 | 1 | 로그인 시도에 상한 |
| FR-210 | 회원가입 | 필수 | 1 | 이메일 중복 거부. 응답이 계정 존재 여부를 알려주지 않는다 |
| FR-211 | 내 정보 조회·수정 | 필수 | 1 | 본인만. 역할·권한 필드는 폼에서 받지 않는다 |
| FR-212 | 회원 탈퇴 | 선택 | 2 | 비활성화가 기본. 주문 이력이 있으면 삭제하지 않는다 |
| FR-213 | 소셜 계정 연결·해제 | 선택 | 1 | 본인이 연결 목록을 보고 해제할 수 있다. 마지막 로그인 수단은 해제할 수 없다 |
| FR-214 | 이메일 인증 | 필수 | 1 | 설정으로 켜고 끈다(기본 켬). 켜져 있으면 인증 전 계정은 글쓰기·주문을 할 수 없다. 인증 링크는 1회용이고 만료가 있다 |
| FR-215 | 회원 프로필 항목 정의 | 필수 | 2 | 운영자가 가입·내 정보에서 받을 항목을 정의한다. **개수 제한이 없다** — 정의는 행이고 값은 JSONB 다 ([DEC-3.9](../.ai/DECISIONS.md), 게시판 커스텀 필드와 같은 구조). 여분 칸을 고정 개수로 만들어 두는 방식은 그 개수를 넘는 순간 `ALTER TABLE` 을 요구한다 |
| FR-216 | 공개 폼 스팸 방지 | 필수 | 6 | 가입·비밀번호 재설정 요청·글쓰기·댓글 폼에 사람이 보지 않는 칸(honeypot)이 있고, 채워 온 제출은 저장하지 않는다. 관리자가 Cloudflare Turnstile 키를 넣으면 같은 폼이 위젯 토큰을 서버에서 `siteverify` 로 확인한다 — 키가 없으면 꺼져 있고 외부 호출도 없다 |
| FR-217 | 회원가입 닫기 | 필수 | 6 | 관리자가 A-201 에서 「회원가입 받지 않음」을 고르면 P-103 의 폼과 제출이 403 이고 공개 화면의 가입 링크가 사라진다. 기본은 받음 — 이 설정이 없던 사이트는 그대로 열려 있다. 닫아도 관리자는 A-401 「사용자 추가」로 계정을 만든다 |
| FR-218 | 아이디 저장 | 선택 | 6 | 로그인 화면에서 「아이디 저장」을 체크하고 로그인에 성공하면 다음 로그인 화면의 이메일 칸이 채워지고 체크가 켜져 있다. 이메일만 30일 남기는 로그인 화면 전용 쿠키(`HttpOnly`·`Path=/login`·`SameSite=Lax`, Secure 는 세션 쿠키와 같다)이고 인증·세션 수명에는 쓰지 않는다. 실패한 로그인은 남기지 않고, 체크를 끄고 로그인하면 지운다. 기본은 끔 |

## FR-3xx 테마

> 테마 시스템은 이 제품의 존재 이유다. 여기서 타협하면 만들 이유가 없다. ([D40](40-theme.md))

| ID | 요구사항 | 우선 | Phase | 완료 기준 |
|---|---|---|---|---|
| FR-301 | 기본 테마는 바이너리에 내장된다 | 필수 | 1 | 파일 하나만 배포해도 사이트가 뜬다 |
| FR-302 | 디스크의 사용자 테마가 내장 테마를 오버라이드한다 | 필수 | 1 | 같은 이름의 템플릿이 디스크에 있으면 그쪽이 쓰인다 |
| FR-303 | 테마 교체에 재컴파일·재시작이 필요 없다 | 필수 | 1 | 관리자에서 테마를 바꾸면 다음 요청부터 적용 |
| FR-304 | 코어가 템플릿 함수맵을 제공한다 | 필수 | 1 | URL 생성, 페이지네이션, 날짜·숫자 포맷, 에스케이프 헬퍼 |
| FR-305 | 테마에 비즈니스 로직을 넣을 수 없다 | 필수 | 1 | 템플릿은 준비된 데이터만 받는다. DB 접근 함수를 노출하지 않는다 |
| FR-306 | 개발 모드에서 템플릿 캐시를 끈다 | 필수 | 1 | 파일을 고치면 새로고침만으로 반영 |
| FR-307 | 테마 업로드(zip) | 선택 | 2 | 압축 해제 경로 검증 필수 (Zip Slip) → [D60](60-security.md) |
| FR-308 | 테마가 요구하는 템플릿 목록이 문서화된다 | 필수 | 1 | 없는 템플릿은 내장 테마로 폴백 |
| FR-309 | 테마 정적 자산(CSS·JS·이미지)을 서빙한다 | 필수 | 1 | 내장 테마는 `embed.FS`에서, 디스크 테마는 파일에서. 테마 디렉터리 밖 파일에 접근할 수 없다 |
| FR-310 | 테마의 로고·파비콘 | 선택 | 6 | 테마가 `theme.json` 의 `logo`·`favicon` 에 `static/` 아래 이미지 경로를 적으면, 그 테마가 활성인 동안 관리자 화면 머리글의 마크와 파비콘, 내장 테마의 공개 머리글 로고와 파비콘이 그것으로 바뀐다(재시작 없이 테마를 바꾸면 따라간다). 지정이 없거나 틀리면(밖을 가리킴·이미지가 아님·파일 없음) 기본 마크·아이콘을 쓰고, 활성화 때 경고한다. 로고는 `<img>` 로만 그린다 |
| FR-311 | 테마가 관리자 화면을 선언한다 (`admin.json`) | 필수 | 6 | 테마가 `admin.json` 에 설정형·모음형 화면과 칸(글·긴 글·숫자·사진·링크·고르기)을 적고 활성화하면 관리자 사이드바에 그 화면이 나오고(A-212), 저장한 값이 공개 템플릿에 `.Theme.<화면 키>` 로 온다. 값이 없으면 선언의 기본값이다. 화면 단위 부여(A-404)가 없는 역할에는 메뉴가 없고 403 이다. 테마를 바꿨다 되돌려도 값이 남고, 선언 오류는 활성화 때 경고한다 (`TestThemeScreensReachTheMenuAndThePage`·`TestThemeScreenNeedsTheScreenScope`, [D41](41-theme-admin.md)) |
| FR-312 | 테마 템플릿이 실패하면 잘린 페이지 대신 500 과 코어 내장 오류 화면이 나간다 | 필수 | 6 | 공개 화면과 조각 응답을 버퍼에 다 그린 뒤 보낸다. 템플릿 실행이 실패하면(없는 필드·함수 인자 형 불일치·테마가 요구하는 기능이 없는 코어) 500 이고 본문은 코어 내장 `error.html` 이며 테마가 실패 전에 쓴 조각이 없다. 로그에 템플릿 이름·요청 주소(재설정 토큰은 가림)·오류가 ERROR 로 남고, 정상 화면의 출력은 그대로다 (`TestThemeTemplateFailureIsA500WithTheBuiltinErrorPage`·`TestBrokenThemeTemplateServesA500NotHalfAPage`, [D17](17-theme-contract.md)) |
| FR-313 | 부팅 때 활성 테마의 `requires` 를 검사한다 | 필수 | 6 | 활성 테마의 `requires` 가 코어보다 높은 채 재시작하면 사이트를 내리지 않고 내장 테마로 뜬다 — ERROR 한 줄, 공개 화면 200, `/healthz` 200, A-602 경고. `theme.active` 는 그대로라 코어를 올리면 그 테마로 돌아오고, 다른 테마를 켜면 경고가 걷힌다. 그동안 A-202 는 고른 테마를 「사용 중」이 아니라 「선택됨」으로 보인다. 개발 빌드처럼 버전을 해석할 수 없거나 `requires` 형식이 깨졌으면 경고만 하고 그 테마로 뜬다 (`TestBootServesTheBuiltinThemeWhenTheActiveOneNeedsANewerCore`·`TestBootOnlyWarnsAboutRequiresOnADevBuild`·`TestBootOnlyWarnsAboutAMalformedRequires`, [D17](17-theme-contract.md)) |

## FR-5xx 게시판

> **게시판마다 테이블을 만들지 않는다** ([DEC-3.9](../.ai/DECISIONS.md)). 커스텀 필드는 JSONB로 간다.
> "설정으로 게시판 뚝딱"이라는 그누보드 경험의 핵심은 FR-502 + FR-503이다.

| ID | 요구사항 | 우선 | Phase | 완료 기준 |
|---|---|---|---|---|
| FR-501 | 관리자에서 게시판을 생성·설정한다 | 필수 | 2 | 이름, 슬러그, 권한, 첨부 허용, 댓글 여부, 스킨 |
| FR-502 | 게시판별 커스텀 필드 스키마를 정의한다 | 필수 | 2 | 필드 이름·타입·필수 여부·선택지를 관리자에서 저장 |
| FR-503 | 템플릿이 필드 스키마를 읽어 폼·목록을 동적 렌더링한다 | 필수 | 2 | 필드를 추가하면 코드 수정 없이 폼에 나타난다 |
| FR-504 | 글 CRUD | 필수 | 2 | 작성·수정·삭제·조회수 |
| FR-505 | 댓글 (대댓글 포함) | 필수 | 2 | 게시판 설정으로 on/off |
| FR-506 | 첨부파일 | 필수 | 2 | 검증 규칙은 [D60](60-security.md) NFR-206 |
| FR-507 | 검색 | 필수 | 2 | 제목·본문. PostgreSQL 전문검색 사용 |
| FR-508 | 페이지네이션 | 필수 | 2 | 큰 오프셋에서도 응답이 무너지지 않는다 |
| FR-509 | 목록 정렬·필터 | 선택 | 2 | 커스텀 필드 기준 정렬 포함 |
| FR-510 | `sitemap.xml` | 필수 | 2 | 발행된 페이지·글만 포함. 쇼핑몰이면 노출 상품과 상품 카테고리도 넣는다 |

| FR-716 | 지도 삽입 (네이버·카카오·구글) | 필수 | 6 | 관리자가 A-201 에 네이버 지도 ncpKeyId·카카오맵 JavaScript 키·구글 지도 API 키와 Map ID 를 넣으면, 에디터의 「지도 넣기」 에서 그 지도사를 골라 장소·주소를 검색하고 지도를 눌러 위치를 정해 본문에 지도 블록을 넣는다. 글 화면은 그 지도사의 공식 SDK 로 지도와 핀을 그린다. 본문에는 스크립트가 들어가지 않고 지도사·좌표·확대·이름만 남으며, 키가 없으면 자리표시 그림과 이름이 보인다 |

| FR-718 | 검색 노출 설정 | 선택 | 6 | 관리자가 「검색 노출」(A-211)에서 기본 설명·대표 이미지·GA4 측정 ID 와 함께 구글·네이버·빙의 소유 확인 값을 넣으면 공개 화면 `<head>` 에 그 메타 태그가 붙는다(태그를 통째로 붙여 넣어도 값만 뽑는다). 「검색 노출 끄기」를 켜면 공개 화면 전부에 `noindex` 가 붙는다(메타 태그와 `X-Robots-Tag` 헤더 — `<head>` 를 덮어쓴 테마도 헤더는 받는다). 검색 노출 태그는 테마 조각 `partials/seo.html` 에 있어 `<head>` 를 덮어쓴 테마가 그것을 부르면 같은 태그를 받는다. `robots.txt` 에 덧붙일 규칙을 적을 수 있고, 지시어(User-agent·Allow·Disallow·Crawl-delay·Sitemap) 줄과 주석 줄이 아니면 저장하지 않는다 |
| FR-719 | 구조화 데이터 | 선택 | 6 | 홈에 WebSite·Organization(사업자 정보가 있으면 상호·주소·전화·이메일·사업자등록번호, `site_url` 이 있으면 활성 테마의 로고를 절대 주소로), 상품 화면에 Product(이름·이미지·설명·가격 KRW·재고 상태)를 JSON-LD 로 싣는다 |
