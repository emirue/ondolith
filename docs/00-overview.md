# D00. 제품 개요

## 한 문장

**Ondolith는 단일 Go 바이너리로 배포되는 오픈소스 CMS + 커머스 플랫폼이다.**
브라우저에서 설치가 끝나고, 테마를 재컴파일 없이 교체하며, 한국형 결제를 지원한다.

## 이름

온돌(溫突) + monolith. 온돌은 집 바닥 전체에 깔려 집 전체를 데우는 기반 설비다.
사이트 전체를 떠받치는 단일 바이너리 모놀리스라는 구조를 그대로 나타낸다.

## 대상 사용자

| 사용자 | 상황 | 이 제품이 해결하는 것 |
|---|---|---|
| **사이트 운영자** | 회사·단체·소상공인 홈페이지가 필요하다. 개발자가 아니다 | 서버 하나에 바이너리 하나. 브라우저에서 설치가 끝난다 |
| **제작 대행사** | 고객사마다 홈페이지+쇼핑몰을 납품한다 | 테마만 갈아끼우면 다른 사이트. PG는 설치처마다 다르게 |
| **테마 개발자** | 디자인을 팔거나 납품한다 | Go를 몰라도 된다. `html/template` 파일만 만진다 |

**대상이 아닌 사용자:** 헤드리스 CMS를 찾는 프론트엔드 팀, 멀티 노드 확장이 필요한 서비스.

## 왜 만드는가

한국에서 이 자리를 채우는 것은 그누보드와 워드프레스다. 각각의 한계가 있다.

| | 잘하는 것 | 문제 |
|---|---|---|
| 그누보드 | 설치가 쉽다. 게시판이 강력하다 | PHP 런타임 필요. 게시판마다 테이블을 만든다. 20년치 취약점 이력 |
| 워드프레스 | 생태계가 크다 | PHP + MySQL 스택. 플러그인 의존. 상시 메모리 |

Ondolith가 노리는 지점: **그누보드의 설치·게시판 경험 + Go 단일 바이너리의 배포·자원 특성.**

## 목표

1. AWS Lightsail 저사양 인스턴스 단일 서버에서 무난히 동작
2. 설치가 브라우저 안에서 완결 (터미널 작업 없이)
3. 런타임 테마 교체 (재컴파일 없이)
4. 관리자 화면에서 게시판·페이지를 생성·설정
5. 한국형 커머스 (토스페이먼츠 우선)
6. 프론트·관리자·API가 하나의 바이너리, 하나의 서버
7. **패치가 쉬울 것** — 바이너리 교체 + 재시작이 전부 (→ [D70](70-operations.md))

## 비목표 (1차 범위 밖)

- 수평 확장, 멀티 노드
- 헤드리스 / API 우선 아키텍처
- 서드파티 플러그인 마켓 (훅 포인트만 열어둔다 → [D10](10-requirements.md) NFR-401)
- 다국어 UI (한국어 우선, i18n 구조만 열어둔다)

## 설계를 지배하는 제약 세 가지

이 셋이 나머지 결정 대부분을 결정한다. 새 제안이 이 중 하나를 깨면 그 제안은 틀렸다.

1. **테마는 런타임에 교체된다** → 렌더링 경로에 코드 생성·사전 컴파일 금지 ([DEC-3.1](../.ai/DECISIONS.md), DEC-3.2, DEC-3.4)
2. **단일 바이너리·저사양 서버** → 무거운 프레임워크·외부 런타임·별도 워커 프로세스 금지
3. **배포형 제품이다** → 설치처마다 DB·PG·도메인이 다르다. 우리 환경을 가정한 하드코딩 금지
