# D16. 데이터 커버리지

**모든 테이블에 대해 "누가 만들고 누가 보여주는가"를 적는다.**

이 표의 목적 하나뿐이다 — **데이터를 소비하는 화면만 만들고 생산하는 화면을 빠뜨리는 사고를
막는 것.** 실제로 그렇게 관리자 화면 6개가 빠져 있었다 ([M8](../.ai/MISTAKES.md)).
요구사항 표도 화면 인벤토리도 그때 완성돼 보였다. 한쪽만 있어도 둘 다 채워진 것처럼 보이기
때문이다.

## 규칙

| # | 규칙 |
|---|---|
| 1 | [D30](30-data-model.md)의 모든 테이블이 이 표에 있어야 한다. 없으면 `make check` 실패 |
| 2 | `만드는 화면`·`보여주는 화면`은 **빈 칸일 수 없다.** 화면 ID이거나 `(괄호 안 사유)`여야 한다 |
| 3 | 여기 적는 화면 ID는 [D11](11-screens.md)에 실재해야 한다 |
| 4 | 테이블을 추가하면 **같은 커밋에서** 이 표에 행을 추가한다 |

`(표시 안 함)` / `(시스템 기록)` 같은 괄호 표기는 **의도적 부재**를 뜻한다. 사유를 못 쓰겠으면
그건 빠진 화면이다.

## 이 표로 찾은 누락

기록으로 남긴다 — 같은 방식으로 또 찾을 수 있다.

| 회차 | 빠져 있던 화면 | 있었던 것 |
|---|---|---|
| 1 | A-509 카테고리 관리 | P-302 (공개 목록) |
| 1 | A-510 송장 입력 | P-505 (배송 조회) |
| 1 | A-205 메일 설정 | P-104 (재설정 메일) |
| 1 | A-206 소셜 설정 | P-106, P-107 |
| 2 | P-111 소셜 계정 연결 관리 | P-107 (연결만 만들고 해제할 곳이 없었다) |
| 2 | A-603 웹훅 수신 이력 | P-905 (기록만 하고 볼 곳이 없었다) |
| 2 | P-510 구매확정 | 상태머신에 전이는 있는데 일으킬 화면이 없었다 |

2회차는 이 표를 만들면서 찾았다. **`보여주는 화면` 칸을 채우려다 빈 것이 드러났다.**

## 아직 정하지 않은 것

미결은 [D18 미결 대장](18-open-decisions.md)에 모아 둔다. 문서마다 표를 두면 결정을 내려도 일부만 지워져 낡은 항목이 남는다.
