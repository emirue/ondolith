# D82. 실행 루프

**[D81](81-work-breakdown.md)의 123개 작업을 멈추지 않고 돌리는 절차.**
무엇을 만들지는 D81이, 어떻게 판정할지는 이 문서가 정한다.

## 지배 원칙

이 넷이 나머지를 결정한다. 새 절차가 이 중 하나를 깨면 그 절차는 틀렸다.

| # | 원칙 | 근거 |
|---|---|---|
| **L1** | **완료는 명령의 exit code로만 판정한다.** "된 것 같다"는 판정이 아니다 | 주관적 확신은 다음 세션에서 재현되지 않는다. 통과는 "검사가 있다"는 뜻이지 "검사가 문다"는 뜻이 아니다 ([M4](../.ai/MISTAKES.md)) |
| **L2** | **작업 순서는 D81의 선행 관계가 정한다.** 여기에 순서를 다시 적지 않는다 | 순서를 두 곳에 두면 갈라진다 ([M9](../.ai/MISTAKES.md)) |
| **L3** | **진행 상태는 D81 행에만 남긴다.** 별도 상태 파일·체크리스트를 만들지 않는다 | 계획과 진행을 다른 파일에 두면 둘 중 하나가 반드시 낡는다 |
| **L4** | **막히면 멈추고 결정한다.** 미결을 추측으로 메우고 진행하지 않는다 | 추측으로 채운 값은 코드에 박힌 뒤에 발견된다 ([D18](18-open-decisions.md)) |

---

## 1. 한 바퀴

```
① scripts/next-task.sh          다음 작업 ID·산출물·완료 기준
② 구현                           D22 9절 순서 안에서
③ 종료 신호 실행                  2절
④ 실패 → ②                      신호가 전부 green 이 될 때까지
⑤ 통과 → D81 행에 완료 표시 → ①
```

**②와 ③ 사이에 사람의 판단이 들어갈 자리가 없다.** ③이 판정한다.

## 2. 종료 신호

두 층이다. **아래층이 green 이어도 위층이 red 면 그 작업은 끝나지 않았다.**

| 층 | 신호 | 언제 |
|---|---|---|
| 공통 게이트 | `make check` | **항상.** build · vet · gofmt · test(-race) · docs · selftest |
| DB 층 | `make test-integration` | 스키마·쿼리·트랜잭션을 건드린 작업 |
| 작업 고유 | D81 그 행의 `완료 기준` | 항상. 대개 이름 붙은 테스트 하나로 표현된다 |

`make check`는 DB가 없어도 돌아야 한다 — DB 테스트는 `ONDOLITH_TEST_DSN`이 없으면
건너뛴다. `make vuln`은 네트워크가 필요해 게이트에 없고 릴리즈 전 필수다
([D21](21-tech-stack.md) 1절).

### 완료 기준을 신호로 바꾸는 규칙

D81의 완료 기준은 대부분 산문이다. 구현자가 그것을 **실행 가능한 하나**로 바꾼다.

| 완료 기준의 형태 | 신호 |
|---|---|
| "…가 거부된다" · "…가 실패한다" | 거부를 단언하는 테스트. **대상 코드를 고장내 실패하는 것까지 확인한다** ([M4](../.ai/MISTAKES.md)) |
| "…가 D15 표와 일치한다" | 문서를 **파싱해** 대조한다. 표를 코드에 다시 적으면 세 번째 사본이 된다 ([M12](../.ai/MISTAKES.md)) |
| "쿼리가 상수 개수다" | 쿼리 수를 세는 통합 테스트 |
| "코드에 …가 없다" | `grep`. 셸 검사면 `scripts/selftest.sh`에 주입 케이스를 같은 커밋에 넣는다 |
| "문서 X가 갱신된다" | `make check`의 `docs` 단계가 이미 강제하는지 확인하고, 아니면 검사를 추가한다 |

## 3. 진행 상태

**완료 표시는 D81 행의 `작업` 칸에 남긴다** (L3).

```
| W1-03 | RBAC 스키마 마이그레이션 **(완료 — `00002_rbac.sql`, `make test-integration`)** | … |
```

괄호 안은 **무엇으로 판정했는지**다. 산출물 경로이거나 돌린 명령이며, 둘 다 나중에
재확인할 수 있다. "완료"만 적고 근거를 비우지 않는다.

`checkdocs.sh`가 검사하는 것:

| 검사 | 막는 사고 |
|---|---|
| 완료 표시된 작업의 산출물 파일이 실재한다 | 만들지 않고 완료로 적기 |
| 선행 ID가 D81에 실재하고 **순환이 없다** | 루프가 영원히 착수 가능한 작업을 못 찾는 교착 |
| 작업 수 요약표가 실제 행 수와 같다 | 요약이 낡아 남은 분량을 잘못 알기 |

## 4. 중단과 재개

**재개 절차는 `scripts/next-task.sh` 한 줄이다.** 세션 밖에 상태가 없으므로
"어디까지 했더라"를 사람이 기억할 필요가 없다.

```sh
scripts/next-task.sh --status   # Phase 별 완료 / 전체
scripts/next-task.sh --all      # 지금 착수 가능한 작업 전부
```

**종료 코드가 다음 행동을 정한다.** 자동으로 도는 루프는 출력이 아니라 이 값을 본다.

| 코드 | 뜻 | 루프가 할 것 |
|---|---|---|
| `0` | 다음 작업을 출력했다 | 계속 돈다 |
| `2` | 남은 작업이 없다 | 정상 종료 |
| `3` | 남았는데 착수 가능한 게 없다 (선행 순환) | **중단.** 선행 관계를 고친다 |
| `1` | 문서를 읽지 못했다 | **중단.** D81이 깨졌다 |

셋을 전부 `0`으로 두면 루프가 **"끝났다"와 "막혔다"를 구분하지 못한다** — 조용히 성공한
것처럼 보이는 [M3](../.ai/MISTAKES.md) 계열이다. 네 코드는 `scripts/selftest.sh`가
픽스처로 고정한다.

착수 가능한 작업이 여럿이면 **[D81](81-work-breakdown.md)의 임계 경로에 있는 것**을
먼저 잡는다. 임계 경로 밖 작업을 먼저 하면 총 시간이 늘 뿐 순서 위반은 아니다.

## 5. 멈춰야 하는 때

L4가 적용되는 경우다. 그 외에는 멈추지 않는다.

| 상황 | 할 것 |
|---|---|
| 완료 기준이 [D18](18-open-decisions.md)의 미결에 걸려 있다 | 결정을 먼저 내리고 대장에서 행을 지운다. 추측값으로 구현하지 않는다 |
| 문서끼리 어긋난다 | 어느 쪽이 옳은지 정해 **양쪽을 고친 뒤** 진행한다. 한쪽만 고치면 [M9](../.ai/MISTAKES.md)가 재발한다 |
| 완료 기준이 판정 불가능한 문장이다 | 판정 가능한 문장으로 D81을 고친다. 그것도 작업이다 |
| 게이트가 환경 때문에 못 돈다 | 사실을 적고 무엇을 검증하지 못했는지 남긴다. 건너뛴 것을 통과로 적지 않는다 |

**게이트를 통과시키려고 단언을 지우거나 약화하지 않는다.** 그것은 작업을 끝낸 것이
아니라 신호를 끈 것이다 ([M3](../.ai/MISTAKES.md), [M4](../.ai/MISTAKES.md)).

## 아직 정하지 않은 것

미결은 [D18 미결 대장](18-open-decisions.md)에 모아 둔다. 문서마다 표를 두면 결정을 내려도 일부만 지워져 낡은 항목이 남는다.
