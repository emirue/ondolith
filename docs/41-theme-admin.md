# D41. 테마 선언 관리자 화면

> 테마가 `admin.json` 으로 관리자 화면(설정형·모음형)을 선언하면, 코어가 그 화면을 그리고 값을
> 저장해 템플릿에 `.Theme` 로 넘긴다. 테마 작성자는 2·7절을, 코어 개발자는 전부를 읽는다.
> 요구사항 FR-311 · 화면 A-212 · 마이그레이션 `00031_theme_content.sql` (11절).

## 지배 원칙

| # | 원칙 | 근거 |
|---|---|---|
| 1 | **테마는 선언만 하고, 화면은 코어가 그린다.** 테마는 관리자용 템플릿·스크립트를 들고 오지 않는다 | 남이 만든 템플릿이 관리자 출처에서 돌면 그 테마가 관리자 세션으로 무엇이든 한다. 테마는 준비된 데이터만 받는다 (FR-305) |
| 2 | **저장된 값은 지우지 않는다.** 테마를 바꾸거나, 선언에서 화면·칸을 빼거나, 화면 종류를 바꿔도 값은 DB 에 남는다. 같은 키로 다시 선언하면 그대로 돌아온다 | 커스텀 필드 삭제가 값을 지우지 않는 것과 같은 규칙이다 ([D14](14-screen-flows.md) 3절 규칙 4) |
| 3 | **권한 목록을 늘리지 않는다.** 권한 하나(`theme.edit_content`)에 **화면 스코프**를 단다 | 권한 목록은 코드가 정하고 마이그레이션이 심는다 ([D15](15-access-control.md) P1). 화면 키를 권한 키에 넣는 것은 2.4절이 게시판에 대해 금지한 `board.free.read` 와 같은 모양이다 |
| 4 | **화면마다 테이블을 만들지 않는다.** 값은 JSONB 다 | [DEC-3.9](../.ai/DECISIONS.md) |
| 5 | **선언 오류는 거부하지 않고 경고한다.** 잘못된 화면만 빠지고 나머지는 쓴다 | `base.html` 하나만 필수인 테마 계약([D17](17-theme-contract.md))을 좁히지 않는다. 로고·파비콘 지정 오류(FR-310)와 같은 자리에서 같은 방식으로 알린다 |

## 1. 범위

**하는 것**: 설정형 화면, 모음형 화면(행 추가·수정·삭제·순서), 칸 6종(글·긴 글·숫자·사진·링크·고르기),
사이드바 메뉴, 화면 단위 권한, 사진 업로드, 템플릿의 `.Theme`, 활성화 때 선언 경고, 작업 로그, 백업.

**하지 않는 것**

| 하지 않는 것 | 이유 |
|---|---|
| 테마가 자기 관리자 템플릿을 들고 오기 | 지배 원칙 1 |
| 칸 종류 추가(체크·날짜·여러 개 선택·본문 편집기) | 요청은 6종이다. 늘릴 때 이 문서의 칸 표와 검증을 함께 고친다 |
| 모음 안의 모음, 화면끼리의 참조 | 요청에 없다. 행 하나는 칸의 평평한 묶음이다 |
| 바뀐·빠진 사진 파일 지우기 | 사진 주소(`/media/{id}`, P-213)는 공개라 글 본문에 복사됐을 수 있다. 지우면 그 글이 깨진다. 편집기 사진과 같은 처지이며 구현 때 [D85](85-gaps.md) GAP-33 에 이 경로를 더한다 |
| 권한 회수 화면 | 지금 A-403·A-404 에 회수가 없다. 이 기능 때문에 따로 만들지 않는다 |
| 끌어다 놓기 정렬 | 순서는 숫자 칸이다 — 메뉴(A-204)와 같은 방식 |
| 내장 테마의 선언 | 내장 테마에는 `admin.json` 이 없다. 테마 화면은 디스크 테마만 갖는다 |

## 2. 선언 파일 `admin.json`

테마 루트(`theme.json` 옆)에 둔다. `static/` 밖이라 공개로 서빙되지 않는다 (FR-309). 없으면 테마 화면이 없다.

```json
{
  "screens": [
    {
      "key": "hero",
      "title": "메인 배너",
      "group": "디자인",
      "order": 10,
      "kind": "settings",
      "fields": [
        {"key": "headline", "label": "큰 제목", "type": "text", "required": true, "default": "환영합니다"},
        {"key": "photo", "label": "배경 사진", "type": "image", "help": "가로 1600px 이상"},
        {"key": "tone", "label": "글자색", "type": "select", "options": ["밝게", "어둡게"], "default": "밝게"}
      ]
    },
    {
      "key": "partners",
      "title": "협력사",
      "kind": "collection",
      "fields": [
        {"key": "name", "label": "이름", "type": "text", "required": true},
        {"key": "logo", "label": "로고", "type": "image"},
        {"key": "link", "label": "누리집", "type": "url"}
      ]
    }
  ]
}
```

**화면**

| 속성 | 필수 | 규칙 |
|---|:---:|---|
| `key` | ✔ | `^[a-z][a-z0-9_]{0,31}$` — 게시판 커스텀 필드 키와 같은 규칙이다. 템플릿에서 `.Theme.hero` 로 바로 쓸 수 있는 이름이어야 한다. 테마 안에서 겹치면 뒤의 것이 빠진다 |
| `title` | ✔ | 1~50자. 메뉴 이름이자 화면 제목 |
| `group` | | 1~30자. 사이드바 묶음 이름. 없으면 「테마」. 코어 묶음과 이름이 같으면 그 묶음에 들어간다 |
| `order` | | 정수. 작은 수가 앞. 없으면 0. 코어 메뉴와 같은 줄에서 정렬되고 묶음의 자리도 그 묶음의 가장 앞 항목이 정한다 — 코어 메뉴는 0~90 을 쓰므로, 테마 묶음을 맨 아래에 두려면 100 이상을 쓴다 |
| `kind` | ✔ | `settings`(설정형 — 값 한 벌) 또는 `collection`(모음형 — 행 여러 개) |
| `fields` | ✔ | 1~30개 |

**칸**

| 속성 | 필수 | 규칙 |
|---|:---:|---|
| `key` | ✔ | 화면 키와 같은 규칙. 화면 안에서 겹치면 그 화면이 빠진다 |
| `label` | ✔ | 1~100자 |
| `type` | ✔ | 아래 칸 종류 표의 여섯 값 중 하나 |
| `required` | | 참이면 값도 기본값도 없을 때 저장을 거부한다 |
| `default` | | 값이 저장되지 않았을 때 템플릿이 받는 값. 그 칸의 저장 검증을 통과해야 한다. `image` 는 기본값을 가질 수 없다 |
| `help` | | 0~200자. 입력칸 아래 안내 |
| `options` | `select` 만 | 1~50개, 각 1~100자, 겹치지 않는다. 다른 종류에 적으면 그 화면이 빠진다 |

**칸 종류와 저장 검증**

| `type` | 화면의 이름 | 입력 | 검증 | 저장 모양 |
|---|---|---|---|---|
| `text` | 글 | 한 줄 | 500자까지 | 문자열 |
| `textarea` | 긴 글 | 여러 줄 | 5,000자까지. 줄바꿈 보존 | 문자열 |
| `number` | 숫자 | 숫자 | 실수. 절댓값 10^15 미만 | JSON 숫자 |
| `image` | 사진 | 파일 하나 | 편집기 사진과 같은 경로 — 6절 | `{"id": 미디어 id, "w": 폭, "h": 높이}` |
| `url` | 링크 | 한 줄 | 2,000자까지. `http`·`https` 절대 주소 또는 `/` 로 시작하는 사이트 안 경로(`//`·`\` 제외) — A-211 대표 이미지 주소와 같은 함수 | 문자열 |
| `select` | 고르기 | 선택 | `options` 안의 값 | 문자열 |

**상한**: 파일 64 KiB, 화면 20개, 화면당 칸 30개, 화면당 사진 칸 10개(편집기 한 번 업로드와 같은 수),
모음형 화면당 행 200개.

**선언 오류의 처리** (지배 원칙 5)

| 오류 | 결과 |
|---|---|
| 파일이 JSON 이 아니다 · 64 KiB 를 넘는다 · `screens` 가 배열이 아니다 | 화면 전부 없음 + 경고 한 줄 |
| 화면 하나의 규칙 위반(모르는 속성 포함 — 오타가 조용히 무시되지 않게) | 그 화면만 빠짐 + 화면 키와 이유를 담은 경고 |
| 화면 20개 초과 | 21번째부터 빠짐 + 경고 |

경고는 **활성화(A-202)** 때 기존 경고(요구 버전·템플릿 계약·로고)와 한 문단으로 보이고, **부팅** 때는
로그에 남는다. 개발 모드(FR-306)는 요청마다 다시 읽으므로 고친 선언이 새로고침으로 반영된다.

## 3. 저장

```
theme_settings (id uuid PK, screen_key text UNIQUE, data jsonb, created_at, updated_at)
theme_items    (id uuid PK, screen_key text, sort_order integer, data jsonb, created_at, updated_at)
               INDEX (screen_key, sort_order)
```

- `screen_key` 는 2절 키 규칙과 같은 `CHECK`. `data` 는 `jsonb_typeof(data) = 'object'` `CHECK`
- 외래키가 없다 — 화면은 테이블이 아니라 테마 파일에 있다. 사진은 `data` 안의 미디어 id 문자열이고
  미디어는 지워지지 않으므로(1절) 가리키는 곳이 사라지지 않는다
- **값은 화면 키 단위다.** 두 테마가 같은 키(`hero`)를 선언하면 같은 값을 본다. 칸 종류가 달라
  저장된 값이 선언과 맞지 않으면 템플릿에는 값이 없는 것으로 넘기고(기본값이 있으면 기본값), 다음
  저장이 덮어쓴다
- **저장은 선언된 칸만 바꾼다.** 선언에 없는 칸의 저장값은 그대로 둔다 — 커스텀 필드의
  `ValidateCustomFields` 가 하는 것과 같다 (지배 원칙 2)
- **종류가 바뀌어도 남는다.** 설정형이던 `hero` 를 모음형으로 바꾸면 `theme_settings` 의 행은 쓰이지
  않을 뿐 남고, 되돌리면 다시 보인다
- 마이그레이션은 두 테이블과 권한(4절)을 함께 더한다. `-- +goose Down` 은 두 테이블을 지우므로
  **내리면 테마 화면 값이 사라진다** — CHANGELOG 에 적는다 (NFR-303·NFR-308)

## 4. 권한

| 항목 | 내용 |
|---|---|
| 권한 | `theme.edit_content` (테마 화면 편집) 하나. 마이그레이션이 심는다 |
| 스코프 | `role_permissions` 에 `theme_screen text NULL` 을 더한다. `NULL` = 모든 테마 화면, 값 = 그 화면 키만 |
| 판정 | `CanOnScreen(perm, key)` = 최고 관리자 ∨ 전역 부여 ∨ 그 화면 키 부여 — 게시판의 `CanOn` 과 같은 식 ([D15](15-access-control.md) 2.4) |
| 불변식 | `theme_screen` 은 `theme.edit_content` 에만, `board_id` 와 동시에 쓸 수 없다. DB 가 앞의 것을 말할 수 없으므로 부여 핸들러와 시드가 같은 함수를 지나고 그 함수에 시험을 둔다 |
| 유일성 | `UNIQUE NULLS NOT DISTINCT (role_id, permission_id, board_id, theme_screen)` |
| 시드 | 최고 관리자(`admin`)는 원래 전부 통과한다. `operator` 에 전역 부여. `editor` 는 부여하지 않는다 — 운영자가 A-403 에서 화면 단위로 준다 |
| 부여 화면 | A-403 의 권한 부여 폼(A-404)에 「테마 화면」 선택을 더한다(빈 값 = 모든 화면). 선택지는 활성 테마가 선언한 화면이다. 서버는 활성 테마가 선언한 키만 받는다 |
| 메뉴 | 판정을 통과한 화면만 사이드바에 나온다. 숨김은 UX 이고 모든 경로가 스스로 판정한다 (D15 P3) |
| 테마를 바꾸면 | 부여 행은 남는다. 다시 그 화면을 선언한 테마를 켜면 그대로 쓰인다 |

## 5. 관리자 화면

화면 번호 하나(A-212)가 아래 경로를 모두 가진다 — 메뉴(A-204)가 경로 넷을 한 번호로 갖는 것과 같다.
보안 유형은 사진을 받으므로 SC-7 이다.

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/admin/theme/{key}` | 설정형: 폼 / 모음형: 행 목록 |
| POST | `/admin/theme/{key}` | 설정형 저장 |
| GET, POST | `/admin/theme/{key}/new` | 모음형 행 추가 폼 / 추가 |
| GET, POST | `/admin/theme/{key}/{id}` | 모음형 행 수정 폼 / 수정 |
| POST | `/admin/theme/{key}/{id}/delete` | 모음형 행 삭제 |

- 활성 테마가 선언하지 않은 `{key}`, 종류가 맞지 않는 경로, 다른 화면의 `{id}` 는 404 다
- **폼은 선언을 읽어 그린다.** 기본값은 입력칸의 `placeholder`(고르기는 「기본값(밝게)」 선택지)로 보인다.
  비운 채 저장하면 값이 없는 것으로 저장되어 기본값이 계속 쓰인다 — 기본값을 폼에 미리 채우면 첫 저장에서
  저장값이 되어, 테마가 기본값을 바꿔도 반영되지 않는다
- **사진 칸**은 지금 사진의 썸네일, 「사진 바꾸기」 파일 칸, 「사진 빼기」 체크를 보인다. 파일도 체크도 없으면
  지금 값을 유지한다
- **모음형 목록**은 순서대로 행을 보이고, 각 행의 이름은 선언 순서상 첫 칸의 값이다(첫 칸이 사진이면 썸네일).
  순서는 행 폼의 「순서」 숫자 칸이다(작은 수가 앞, 같으면 먼저 만든 행이 앞). 새 행의 순서 칸은 지금 최댓값 + 1 로
  채워져 맨 뒤에 붙는다. 200행이면 추가 단추 대신 상한을 알린다
- 거부는 422 로 같은 폼을 다시 그리고, 적은 값과 칸 옆 오류 문구를 남긴다 — 다른 관리자 폼과 같다
- 관리자 화면 제목(탭)은 선언의 `title` 이다

## 6. 사진

- **편집기 사진과 같은 저장소를 쓴다**: `MediaStore.Save` — 확장자 허용목록과 내용 감지(NFR-206), 줄이기,
  방향 세우기, EXIF 제거, 썸네일. 파일은 파일 저장소 설정(A-210)대로 로컬 또는 S3 에 간다 (FR-717)
- **파싱보다 먼저 크기를 막는다**: 본문 상한 = 그 화면의 사진 칸 수 × 한 장 상한 + 1 MiB 로
  `MaxBytesReader` 를 건 뒤에 `ParseMultipartForm` 을 부른다. 한 장 상한은 첨부와 같은 설정이다
- 거부 문구는 편집기와 같은 함수(`editorMessage`)에서 온다 — 「jpg·png·gif·webp 사진만」 등
- 폭·높이는 저장 때 `data` 에 함께 적는다. 공개 화면을 그릴 때 미디어 표를 다시 읽지 않기 위해서다

## 7. 템플릿이 받는 것 — `.Theme`

모든 공개 화면의 뷰 모델에 `.Theme` 를 더한다 ([D17](17-theme-contract.md) 「뷰 모델 규약」).

| 화면 종류 | `.Theme.<화면 키>` |
|---|---|
| 설정형 | 칸 키 → 값의 맵. **선언된 칸은 전부 키가 있다** |
| 모음형 | 행의 목록(순서대로). 행마다 칸 키 → 값의 맵. 행이 없으면 빈 목록 |

| 칸 종류 | 값 | 값도 기본값도 없을 때 |
|---|---|---|
| 글·긴 글·링크·고르기 | 문자열 | `""` |
| 숫자 | 소수부가 없으면 정수(int64), 있으면 실수 — 실수 1000000 은 템플릿에서 `1e+06` 으로 찍힌다 | 없음(`nil` — 아무것도 찍히지 않고 `if` 는 거짓) |
| 사진 | `.URL`(`/media/{id}`)·`.Thumb`(`/media/{id}/thumb`)·`.Width`·`.Height` | 빈 값 — `{{if .Theme.hero.photo.URL}}` 로 가른다 |

```html
{{with .Theme.hero}}
  <section class="hero hero--{{.tone}}">
    {{if .photo.URL}}<img src="{{.photo.URL}}" width="{{.photo.Width}}" height="{{.photo.Height}}" alt="">{{end}}
    <h1>{{.headline}}</h1>
  </section>
{{end}}
{{range .Theme.partners}}<a href="{{.link}}">{{.name}}</a>{{end}}
```

- **읽는 비용**: 활성 테마가 선언한 화면이 없으면 질의가 없다. 있으면 공개 화면 하나에 질의 두 번
  (설정형 키 전부를 한 번, 모음형 키 전부를 한 번). 선언은 로더마다 한 번 읽는다(개발 모드는 매번) —
  로고·파비콘(FR-310)과 같다. 작은 서버(NFR-101)에서 메뉴를 요청마다 읽는 것과 같은 크기다
- 값은 html/template 이 문맥에 맞게 이스케이프한다. 링크는 저장 때 스킴을 막았고(2절), 긴 글의 줄바꿈은
  테마가 CSS `white-space: pre-line` 으로 보인다. `template.HTML` 로 넘기는 값은 없다
- 관리자 화면(코어 템플릿)에는 `.Theme` 가 없다 — 공개 화면만 받는다

## 8. 기록과 백업

- **작업 로그**: 설정 저장·행 추가·수정·삭제를 동작 `theme.edit_content`, 대상 `theme_screen`(화면 키)·
  `theme_item`(행 id)로 남긴다. 요약은 화면 이름과 동작이고 **값은 남기지 않는다**. A-601 이름표는
  「테마 화면 편집」. [D15](15-access-control.md) 7절 「공개 화면의 출력을 바꾸는 관리자 변경」에 해당한다
- **백업**: 두 테이블은 `pg_dump` 에, 로컬 사진은 업로드 폴더 묶음에 들어간다 (A-604, FR-713·FR-715).
  S3 를 쓰면 사진은 백업 zip 에 없다 — 파일 저장소 설정(A-210)의 백업 규칙과 같다

## 11. 마이그레이션 `00031_theme_content.sql`

**새 표 둘, `role_permissions` 의 컬럼 하나와 제약 둘, 권한 한 행과 부여 한 행이다. 기존 행은 고치거나 지우지 않는다.**
goose 는 마이그레이션 파일 하나를 트랜잭션 하나로 돌린다(공식 README, 이 파일에 `-- +goose NO TRANSACTION` 이 없다) —
중간에 실패하면 전부 되돌아가고 부팅이 멈춘다. 반쯤 적용된 스키마는 남지 않는다.

### 11.1 Up 이 하는 일

| # | 문 | 기존 데이터에 미치는 것 |
|---|---|---|
| 1 | `CREATE TABLE theme_settings` | 없다 — 새 표 |
| 2 | `CREATE TABLE theme_items` + `theme_items_screen_sort_idx` | 없다 — 빈 표의 인덱스라 즉시 끝난다 |
| 3 | `ALTER TABLE role_permissions ADD COLUMN theme_screen text CHECK (…)` | 기존 행은 `NULL` — 지금까지의 전역·게시판 부여 뜻이 그대로다. 기본값 없는 NULL 컬럼이라 표를 다시 쓰지 않는다 |
| 4 | `ADD CONSTRAINT role_permissions_one_scope CHECK (board_id IS NULL OR theme_screen IS NULL)` | 기존 행은 `theme_screen` 이 NULL 이라 전부 통과한다 |
| 5 | `role_permissions_uniq` 를 지우고 같은 이름으로 `(role_id, permission_id, board_id, theme_screen)` 유일성을 만든다 | 기존 행은 넷째 칸이 모두 NULL 이고 `NULLS NOT DISTINCT` 라, 옛 셋 칸 유일성을 지키던 행은 새 제약도 지킨다. 이름이 같아 부여 질의(`ON CONFLICT ON CONSTRAINT role_permissions_uniq`)는 그대로다 |
| 6 | `INSERT INTO permissions` — `theme.edit_content` (`is_scoped = false`) | 새 행. `is_scoped` 는 게시판 스코프를 뜻하므로 거짓이다 — 화면 스코프는 `auth.ValidateScreenGrant` 가 정한다 |
| 7 | `INSERT INTO role_permissions` — `operator` 에 전역 부여 | 새 행. `JOIN roles` 라 `operator` 가 없는 설치처는 아무것도 넣지 않는다(실패하지 않는다). `admin` 은 superuser 라 부여가 필요 없다 |

### 11.2 올리는 절차

[D70](70-operations.md) 「업그레이드 절차」 그대로다 — **백업 → 바이너리 교체 → 재시작.** 재시작하면 부팅이 대기 마이그레이션을
적용한 뒤에 요청을 받는다. 손으로 SQL 을 돌리는 단계는 없다.

올린 뒤 확인:

- 관리자 「시스템 정보」(A-602)의 대기 마이그레이션이 0 이다
- 또는 DB 에서

```sql
SELECT max(version_id) FROM goose_db_version;                                   -- 31
SELECT key, is_scoped FROM permissions WHERE key = 'theme.edit_content';         -- theme.edit_content | f
SELECT count(*) FROM role_permissions WHERE theme_screen IS NOT NULL;             -- 0 (아직 아무도 화면 단위로 주지 않았다)
```

- 테마 화면을 쓰려면 `admin.json` 이 든 테마를 올리고(A-203) 켠다(A-202). 선언 오류는 그 활성화 화면이 경고한다

### 11.3 되돌리는 길

| 하려는 것 | 길 |
|---|---|
| 바이너리만 이전 릴리즈로 (스키마는 31 그대로) | 된다 — 이전 바이너리는 모르는 표·컬럼을 읽지 않고, 유일성 제약 이름이 같아 부여 질의도 그대로 돈다. 값은 남아 다시 올리면 돌아온다. 부팅 로그에 「어떤 라우트도 쓰지 않는 권한: theme.edit_content」 경고가 한 줄 나온다. **단, 활성 테마의 템플릿이 `.Theme` 을 쓰면 이전 바이너리에서는 그 자리에서 렌더링이 실패한다** (`can't evaluate field Theme`) — 상태 코드는 이미 200 으로 나가 페이지가 잘린다. 되돌리기 전에 `.Theme` 을 쓰지 않는 테마(내장 테마 등)로 바꾼다 |
| 스키마까지 이전 상태로 | **업그레이드 전 백업을 복원한다** ([D70](70-operations.md) 「다운그레이드」, NFR-308). 이 바이너리에는 Down 을 돌리는 명령이 없다. `-- +goose Down` 은 시험(`TestEveryMigrationRollsBackCompletely`)이 매번 적용하고 되돌려 흔적이 남지 않음을 확인하는 대상이다 |
| Down 을 돌렸을 때 잃는 것 | `theme_settings`·`theme_items` 의 값 전부, 화면 단위 부여 행, `theme.edit_content` 와 그 부여. 사진 파일과 `media` 행은 남는다 |
